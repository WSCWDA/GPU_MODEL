# 图形与计算线实践大纲（初级 → 高级两阶段）

> 性质：**目标架构大纲与权威规格**，定义两阶段划分、36 章边界、E/S 场景集、配置键、能力边界与校验模型。
> 结构：**初级 1~9、高级 10~36**；图形线与计算线共用内存、缓存、队列、ISA、调度与错误模型；计算能力不新增硬件章，按 §4.7 落到章内子里程碑 + 35.5 计算驱动。
> 硬约束：契约先行、单章单通路、结果确定、时间无关、单条 draw/dispatch 语义；两个阶段都不建模周期、功耗、DRAM 时序。
> 仿真定位：**功能行为等价仿真**，不是周期精确仿真——硬件单元用 FSM 有限状态机 + valid/ready 功能级握手建模，不仿真时钟周期、不仿真流水线寄存器每拍变化、不仿真总线时序。
> 权威顺序：本文件 → `roadmap.md` → `architecture-design.md` → `stage1/`、`stage2/` 章文档；冲突以本文件为准。

---

## 1. 为什么分两个阶段

把"看懂原理"和"做全硬件"压在同一条纵深线上的问题：前 12 章都在打地基，第一次画出三角形要到第 18 章；学习曲线前重后轻，且任何契约返工都会打断整条链。

两阶段的切法：

| | 初级（原理最小管线） | 高级（硬件级完整实现） |
|---|---|---|
| 回答的问题 | GPU 是怎么把一条 draw 变成像素的 | 真实 GPU 为什么这样实现、边界与并行行为如何 |
| 实现深度 | 每单元只做**一种**最简实现，可单步跟踪 | 补齐多通路、缓存、并行、抢占、多 API |
| 文档形态 | 9 章严格线性，**第 9 章端到端出图** | 在初级产物上逐单元替换/扩展，允许分支并行 |
| 验收方式 | 全图逐字节（几何与滤波足够简单） | 固定探针点比对（§7） |
| 执行策略 | 仅串行 | 串行 + 硬件对齐并行 |
| 最终产物 | 能画三角形/贴图/简单模型的 CPU 模拟器 | 完整虚拟 GPU + HLI + 三套 UMD |

核心原则：**初级阶段允许"不真实"，但不允许"不清楚"**。每处简化必须显式登记（§3.3），且必须能指出高级阶段由哪一章替换（§4.3）。

## 2. 两阶段总览

| 阶段 | 章 | 目标 | 阶段门禁 |
|---|---|---|---|
| 初级 | 1~9 | 最小可用渲染通路，端到端出图 | E0~E5 全绿，全图逐字节稳定 |
| 高级 | 10~36 | 真实硬件行为、并行、多引擎、多 API、计算线 | S0~S19 全绿，探针一致 + DoD 全过 |

体量口径：**S** = 单点能力；**M** = 一个完整单元；**L** = 单元 + 跨单元契约，需章内里程碑推进。

### 2.1 两条纵向线：图形线与计算线

高级阶段的 27 章不是只有图形一条路。底层 10~20、32~34、36 为两条线共用，上层分成两条可独立验收的纵向功能线：

| 线 | 主通路 | 专有单元 | 驱动层 | 引入阶段 |
|---|---|---|---|---|
| 图形线 | IA → VS → 裁剪/PA → 光栅 → PS → OM → 输出 | 22~28、34（图形侧） | 35.2~35.4（Mesa 风格） | 初级起点即图形 |
| 计算线 | dispatch → workgroup 映射 → wave → LDS/原子 → 写回 | 15、29、30、31、33（计算侧） | 35.5（MUSA 风格） | 高级阶段引入 |

**共用单元**：设备/环/CP（10）、地址与堆（11）、缓存（12）、分歧与调度（15）、ISA（16）、编译器（17~19）、资源绑定（20）、队列与同步（32）、查询（34）、错误恢复（36）。共用单元不得为图形或计算任一方向特化（§9）。

**计算支持度**：

| 计算能力 | 落位 | 缺口 | 补强 |
|---|---|---|---|
| SIMT 执行、分歧、ISA、编译器 | 15~19 | 无 | 保持共用 |
| LDS / 原子 / barrier / 内存序 | 30 | 缺 workgroup 与 device 作用域判据 | 30 子里程碑 + S19 |
| 波内归约与计算内建 | 29 | 缺计算侧判据 | 29 子里程碑 + S18 |
| 三维 grid/block/thread 与 workgroup 映射 | 31 提及 | 无完整语义与越界规则 | 31 子里程碑 + S18 |
| kernel 参数 / module / function | 20 提及常量缓冲 | 缺 kernel 对象与参数缓冲 | 20 + 35.5 |
| 间接 dispatch | 33 只写间接 draw | 无 dispatch 判据 | 33 + S19 |
| 计算队列 / 异步计算 / 图形互操作 | 32 提及多队列 | 无计算专有判据 | 32 + S19 |
| 计算驱动运行时（MUSA-like） | 无 | **整层缺失** | 35.5 |

结论：硬件单元层已具备计算所需的全部原语，缺的是**纵向通路成文**与**计算驱动层**，按 §4.7 补齐后结构可支撑计算线。

## 3. 初级：原理最小管线（1~9 章）

### 3.1 目标与产物

- **目标**：一条 draw 的完整链路可读、可跑、可断言——应用提交 → 环 → 取命令 → 读地址 → 取顶点 → 执行着色器 → 裁剪光栅 → 合并写回 → 上屏。
- **产物**：单线程 CPU 模拟器 + 5 个场景程序；每个单元有一个可单步观察的状态视图（`--trace` 打印每步输入输出）。
- **不追求**：性能、并行、真实边界行为、API 兼容。这些全部归高级阶段。

### 3.2 章节总览

| 章 | 文档（`stage1/`） | 单元 | 职责 | 体量 |
|---|---|---|---|---|
| 1 | `01-contracts-min.md` | 契约最小集 | 冻结句柄/命令包头/像素格式/地址约定/浮点与确定性规则 | S |
| 2 | `02-device-and-ring-min.md` | 设备 + 单环 | MMIO 最小寄存器块、doorbell、单环读写指针、submit → complete | M |
| 3 | `03-flat-memory.md` | 平坦内存 | 单一 VA 空间、直接映射、bump 分配器、资源上传/读回 | M |
| 4 | `04-simt-single-wave.md` | SIMT 单波 | warp32、VGPR/SGPR/谓词、无分歧指令流、组内线性执行 | M |
| 5 | `05-isa-min.md` | 最小 ISA | 约 20 条指令、线性编码、汇编器/反汇编器、VS/PS 样例 | M |

**第 6 章是初级的重心**：它把"顶点 → 图元 → 像素"三段固定功能一次串起来，允许 L 级体量但要求章内拆成 `M6.1` IA / `M6.2` 裁剪视口 / `M6.3` 光栅 / `M6.4` 合并四个可单独验收的里程碑（与 `roadmap.md` §2.1 登记一致，Q-41）。

### 3.3 初级简化假设（必须登记，高级逐条替换）

| 项 | 初级实现 | 高级替换章 |
|---|---|---|
| 地址 | 单一连续 VA，直接映射物理，无 TLB、无页错误 | 11 |
| 存储 | 扁平显存字节数组，无 L1/L2、无写缓冲 | 12 |
| 提交 | 单队列、单环、容量足够不回绕、无中断/watchdog | 10 |
| 执行 | 单波、单 SIMD、**着色器内禁止分支**（无分歧概念） | 15、16 |
| ISA | ~20 条指令子集，线性编码，无压缩编码 | 16 |
| 着色器来源 | **不引入编译器**，全部手写 ISA；E2/E3/E4 的 VS/PS 用汇编写死 | 17~19 |
| 工作量类型 | **不覆盖计算**，只有图形 draw；无 dispatch、无 workgroup | 29~31、35.5 |
| 固定功能 | 非索引 IA、无 HS/DS/GS、无 MSAA、固定深度比较 | 22~28 |
| 纹理 | RGBA8、nearest、单层、无 mip、无 sRGB、无采样器对象 | 21 |
| 资源绑定 | 常量/顶点/纹理直接用指针传递，无描述符堆 | 20 |
| 显示 | 单 RT、双缓冲、提交后读回，不建模 vsync/翻转链 | 13 |
| 上下文 | 单上下文，无驻留逐出、无抢占 | 14 |
| 同步 | 单队列顺序完成，无 semaphore/fence 硬件对象 | 32 |
| 执行策略 | 仅 `serial`，无缓存/TLB 统计 | 31 |
| API 层 | 无 HLI/UMD，场景直接调用引擎 C++ 接口 | 35 |
| 校验 | 全图逐字节 + 少量结构断言 | §7 探针模型 |

> 初级简化假设一旦登记，高级阶段不得"悄悄改掉"——替换必须在对应章节按契约变更流程走（§10.3），并回归初级场景 E0~E5。
> 计算线不在初级登记为"简化"，而是**整体推迟**：初级只交付图形通路，计算在高级阶段作为第二条纵向线一次性引入（§4.7）。

### 3.4 初级依赖链

```
1 契约最小集
└ 2 设备与单环
   └ 3 平坦内存
      └ 4 SIMT 单波
         └ 5 最小 ISA
            └ 6 固定功能最小集
               └ 7 纹理最小集
                  └ 8 帧输出
                     └ 9 端到端验收
```

严格线性，不允许跳章：第 4 章前不能执行任何着色器，第 6 章前不能产生任何像素，第 8 章前不能看到画面。这是初级阶段的"爬升纪律"。

### 3.5 初级场景（E0~E5）

| ID | 场景 | 输入 | 产物 | 主判据 |
|---|---|---|---|---|
| E0 | `scene_e0_selftest` 契约与工具自检 | 无 | 断言结果、汇编往返产物 | 结构体/枚举/命令包头断言全绿；汇编→二进制→反汇编→再汇编二进制相同 |
| E1 | `scene_e1_clear_present` 清屏上屏 | 0.25 灰 | 全屏 (63,63,63,255) | 全图逐字节等于背景色；读回缓冲 = 显存内容；双缓冲前后帧可区分 |
| E2 | `scene_e2_triangle` 渐变三角形 | 3 顶点 RGB | 灰底 + 渐变三角 | 全图逐字节匹配固定基线（初级的核心兜底判据）；退化三角形不写像素 |
| E3 | `scene_e3_textured_quad` 纹理四边形 | 2×2 纹素 + uv | 四象限色块 | nearest 全图逐字节；UV 越界 clamp 行为确定 |
| E4 | `scene_e4_mesh` 非索引大网格 | 约 1 千三角形 | 模型轮廓 | 单条 draw、非背景像素比例、包围盒像素可复算 |
| E5 | `scene_e5_end_to_end` 端到端最小帧 | 复用 E2/E3/E4 | 一帧完整画面 | 三条独立 draw 共用同一帧；全图逐字节稳定；两次运行一致 |

初级阶段全图逐字节是**刻意选择**：初级没有浮点滤波、没有 MSAA、没有并行，逐字节最容易实现也最容易定位问题。一旦进入高级阶段引入并行，就切换为探针模型（§7），全图逐字节只保留为 `--dump-all` 调试。

### 3.6 初级阶段门禁

1. E0~E5 全绿，且两次运行逐字节一致；
2. 每条简化假设（§3.3）都能在代码中定位到唯一实现点（便于高级替换）；
3. 每章有一份样例输出，作为"这一章到底做了什么"的教学材料；第 1 章无 shader printf / wave trace，以 `GD_LOG` 输出样例代替 `--trace` 样例（Q-41）；
4. 未通过门禁不进入高级阶段——高级只做替换，不做补课；
5. E0~E5 的场景输入（几何、纹理、配置参数）**永久冻结**：高级阶段只允许改校验口径（探针/容差），不得改输入数据。

## 4. 高级：硬件级完整实现（10~36 章）

### 4.1 目标与产物

- **目标**：在初级通路上逐单元替换为真实硬件行为，补齐多通路、缓存、并行、抢占、多引擎、多 API。
- **产物**：完整虚拟 GPU（HLI + 硬件单元）+ Vulkan/D3D12/OpenGL 三套 UMD + CPU 参考模型校验工具链。
- **继承关系**：高级不是重写，而是"**初级哪一章 → 高级哪一章替换**"的连续演进（§4.3）；初级场景 E0~E5 全程保留为回归集。

### 4.3 初级 → 高级升级路径

### 4.7 计算线与驱动分层（借鉴 MUSA / Mesa）

#### 4.7.1 计算最小通路

```
kernel（编译器产物或手写 ISA） → module / function 对象 → kernel 参数缓冲
→ dispatch(grid, block) 命令包 → CP 派发 → workgroup 分配到 CU / SIMD
→ wave 调度 → LDS / 原子 / barrier → 全局内存或图像写回
→ fence / 完成通知 → 查询与统计
```

与图形线的三点本质差异：

1. 没有 IA / 光栅 / OM，输入是 grid 与参数缓冲，输出是内存而不是像素；
2. **workgroup 是调度单位、wave 是执行单位**，二者映射必须显式建模（block 维度、越界 work-item、grid 边界的部分 workgroup）；
3. 内存作用域（workgroup / device）与 barrier 是正确性核心，不是可选优化。

#### 4.7.2 借鉴 MUSA 的计算驱动分层

MUSA 只作为**对象模型与调用路径的借鉴对象**，不做 API 兼容、不做二进制兼容、不做性能模型。

| MUSA 概念 | 本项目对应 | 落位 | 一期 |
|---|---|---|---|
| Runtime API（alloc / memcpy / launch） | 计算驱动的用户态入口 | 35.5 | 做 |
| Driver API（context / module / function / stream / event） | 计算驱动对象模型 | 35.5 | 做 |
| kernel 参数与 launch config | HLI dispatch 包 + 参数缓冲 | 20、33、35.1 | 做 |
| stream / event | 队列 + timeline semaphore / fence | 32 | 复用 |
| unified / pinned memory | 内存域模型（HOST_VISIBLE / HOST_COHERENT） | 11 | 做 |
| occupancy / 性能调优 | 只输出 wave 数与占用统计，不建模占用率 | 31、34 | 不做性能 |
| MUSA 二进制 / API 兼容 | 不做 | — | 不做 |

**对象粒度（35.5 实现前冻结）**：

- `context` = HLI device + KMD context（ASID），一期 1:1:1；销毁前所有 stream 必须已同步。
- `module` = 自有头 `MUSA_MODULE_HDR` + 代码段 + 符号表（`name / entryOffset / paramBytes / vgprCount / ldsBytes`），常驻 GART；不引入 ELF/COFF，不做重定位。
- `function` = module 内入口（`codeBaseVa + entryOffset` + 参数布局）；分支用 pc 相对偏移，因此加载不需要地址修补。
- `stream` = 1:1 映射一个 HLI 队列，stream 内顺序即队列顺序；不允许多队列，优先级创建时声明、不可变。
- `event` = 独立对象 `{queueId, timelineValue, state}`；Record 在命令流插 `SIGNAL`，Wait 插 `WAIT`，Query 非阻塞读状态；值域复用队列 timeline，不复用 fence 对象。
- kernel 参数由驱动打包：应用按签名提交 `ArgPack{ptr, bytes}[]`，驱动写入 GART `HOST_VISIBLE | HOST_COHERENT` 参数缓冲并生成 `KernelArgsLayout`；应用直接给参数 VA 的 `LaunchWithParamBuffer` 留二期。
- 35.5 不新增 HLI 接口：dispatch 走已有 `DISPATCH` 包与 compute pipeline，队列与同步走第 32 章原语。

#### 4.7.3 借鉴 Mesa 的图形驱动分层

| Mesa 概念 | 本项目对应 | 落位 |
|---|---|---|
| State Tracker（GL / Vulkan 前端） | UMD-OpenGL / UMD-Vulkan | 35.4 / 35.2 |
| Gallium（screen / context / CSO） | HLI 对象模型（screen / context / 不可变状态对象） | 35.1 |
| NIR（SSA IR） | 17 章 SSA IR（形状参考，不照搬指令） | 17 |
| NIR → 后端 lowering | 18 章指令选择与寄存器分配 | 18 |
| Winsys（环提交 / doorbell） | 设备环 + CP | 10 |
| llvmpipe / softpipe | 光栅与插值的实现参照 | 25 |

边界：不引入 Mesa 代码、不追求 Mesa 内部接口兼容；只借鉴分层、对象生命周期与 IR 形状。

#### 4.7.4 计算线场景与判据

S18、S19（§4.5）是计算线的专属验收入口；S10 继续承担组内归约与原子，S12 承担多引擎交错，S14 承担全阶段 UAV。

#### 4.7.5 计算线门禁

1. S18/S19 在 `serial` / `parallel` 下硬判据一致；
2. 共用单元不得出现"图形专用"或"计算专用"分支；HLI 侧按命令包类型区分，硬件单元按包类型派发；

### 4.8 内存管理模型（11 章落地，初级 flat 为先导）

#### 4.8.1 三类内存地址与唯一访问通道

| 地址类型 | 含义 | 使用范围 |
|---|---|---|
| `HostVa` | CPU 主机虚拟地址 | 仅 KMD/UMD/上层工具使用 |
| `GpuVAddr` | GPU 虚拟地址 | **`hw_sim` 硬件单元全部只使用此类型** |
| `PhysAddr` | GPU 物理地址 | 页表内部使用 |

硬规则：**硬件单元内部永远禁止直接解引用主机 CPU 指针**，全部经 `IMemorySubsystem::Translate` 翻译；初级 flat 内存中 Translate 是恒等映射，但接口必须保留，高级 11 章直接替换实现、上层代码无需改动。

#### 4.8.2 堆管理器行为约定（高级 11 章）

| 堆 | 分配策略 | 失败行为 |
|---|---|---|
| `VRAM` | 空闲链表分配 | `OutOfMemory` |
| `GART` | bump 分配 + 容量上限，**不做碎片整理**（对齐真实硬件行为） | `OutOfMemory` |
| `System` | KMD 主机侧内存 | — |

全部堆支持输出快照 dump。

#### 4.8.3 KMD 内存池（补充）

`kmd` 层引入**内存池**概念（类似操作系统段页式管理与 STL 分配器的分层）：

- KMD 维护 GPU 地址空间预算与页粒度管理（段 → 页 → 小对象）；
- 小内存分配走对象池 / 缓存池，减少对大堆空闲链表的压力；大块分配仍走堆管理器；
- 分配元数据（标签 / 逻辑时间 / 大小 / VA）由 KMD 记录，供内存快照与泄漏检测复用。

#### 4.8.4 主机-GPU 缓存同步语义

区分 `HOST_VISIBLE` / `HOST_COHERENT`，以及 `Flush`（CPU 缓存写回 GPU）、`Invalidate`（GPU 修改后 CPU 缓存失效）。初级 flat 内存简化为全部 coherent；高级 11 章完整实现内存域与 flush/invalidate。

#### 4.8.5 分配确定性与内存 Sanitizer

- **分配确定性**：所有随机行为绑定可复现伪随机种子，禁止直接调用主机全局 `rand()`；分配器 VA 序列必须可复现——初级 bump 天然可复现，高级 11 章堆管理器支持配置种子，多次运行 GPU VA 分配序列完全一致。
- **GPU 内存 Sanitizer**（`mem_sanitizer=on/off`，默认关，高级 A）：不是操作系统 ASAN，而是内存子系统内部检查，捕获 GPU 侧越界读写、GPU 侧 use-after-free（资源已释放仍被访问）、读取未初始化 GPU 内存；开启显著降低性能，CI 部分测试打开、日常默认关闭。属于调试工具，不混入硬件核心执行路径。
- **分配元数据与泄漏检测**：每块分配记录标签 / 逻辑时间 / 大小 / GPU VA，可导出内存快照 dump；`tools/mem_audit` 离线解析，检测 GPU 内存泄漏与存活分配统计。

## 5. 分层模型（初级直连 → 高级 HLI / UMD / 计算驱动）

```
初级：  场景 ──submit(draw_desc)──> 薄提交门面 ──> 硬件单元（1~9 章）

高级图形：应用 ──> OpenGL/Vulkan/D3D12 ──> 图形 UMD（Mesa 风格） ──┐
高级计算：应用 ──> 计算 Runtime/Driver（MUSA 风格） ──> 计算驱动 ──┤
                                                                  ├─> HLI ──> 硬件单元（10~34、36）
```

- 初级"薄提交门面"只暴露提交与等待两类入口（`submit(draw_desc)` / `wait()`），不做序列化、不带 API 语义；场景代码只依赖门面，不直接 include 任何硬件单元头文件。
- 高级 35.1 用 HLI 替换该门面，`apps/scene_*` 的入口签名保持不变，保证 E0~E5 场景可在 HLI 路径下直接回归。
- 图形 UMD 与计算驱动是**并列**的两条上层，都只向下依赖 HLI；HLI 必须同时容纳图形命令包与计算命令包，不得只按图形设计。

| 层 | 出现阶段 | 职责 | 禁止 |
|---|---|---|---|
| HLI（35.1） | 高级 | 表达虚拟硬件原生能力；对象创建、资源分配、描述符、命令组装；图形与计算共用包格式 | 不做 API 兼容 workaround；不带 API 专属结构体/枚举/错误码 |
| 图形 UMD（35.2~35.4） | 高级 | 对象映射、命令翻译、API 状态修补、隐式状态模拟（Mesa state tracker 做法） | 不得改写 HLI 输出包语义；不得下渗到硬件单元；**不得自行拼包或分配包号（含 `pal/cmd_gen`），包一律经 `IHliCommandList` 生成**（ADR-022、Q-66） |
| 计算驱动（35.5） | 高级 | context/module/function/stream/event、kernel 启动、参数打包（MUSA 对象模型） | 不得绕过 HLI；不得为图形特化 |
| 硬件单元（10~34、36 + 初级 1~9 演进） | 两阶段 | 消费命令包、状态机、SIMT、光栅、内存、硬件同步；按包类型派发 | 不得分支判断上层是哪一套 UMD 或哪个计算 runtime |

**硬约束**：无论调用路径（直连 HLI / 任意图形 UMD / 计算驱动），同一场景输入必须输出逐字节一致结果（S17）。

**HLI ≠ Vulkan API，HLI 包 ≠ VkCommandBuffer**：HLI 只取"贴近硬件"那部分；UMD 把 API 命令缓冲翻译成一串 HLI 硬件包，二者不是同一对象。

**HLI 计算能力**：HLI 必须同时暴露 dispatch 命令包、kernel 参数与描述符绑定、图形/计算共用的 fence 与 query，不得要求计算线走独立硬件通路。

**与真实 KMD/UMD 的差异**：真实 UMD 内含着色器前端与后端编译；本模拟器的编译固定在 17~19 章，35.2~35.5 只消费已编译的 ISA/blob，不重复实现编译器。

**README 与代码分层的对应**：代码依赖方向仍为 `common → hw_sim → firmware → kmd → hli → umd → apps`（详见 `../architecture-design.md` §2.1）；初级阶段跳过 `hli/umd` 两层，场景经薄提交门面调用 `hw_sim`，高级 35 章再补齐这两层。

### 5.1 硬件语义与驱动语义隔离（分层铁律）

模拟器内两类行为必须严格划清边界，避免常见模拟器陷阱：

1. **硬件语义层（`hw_sim` / `firmware`）**：只模拟硬件行为。非法输入不做任何软件层面修复、workaround、兼容修补——非法包、越界访问，硬件该报错就报错、该产生脏数据就产生脏数据、该触发复位路径就复位。
2. **驱动语义层（`kmd` / `hli` / `umd`）**：在这里实现驱动兼容、状态修补、参数转换，对应真实 Mesa / MUSA 驱动的软件逻辑。

**硬性约束**：任何上层 API 兼容 workaround **只允许放在 UMD 层**；禁止为了上层测试跑通，在硬件单元内部偷偷修正非法输入。

### 5.2 故障分层（三类，禁止混淆）

| 故障类型 | 处理位置 | 行为 |
|---|---|---|
| 硬件故障：非法命令包、非法 ISA、GPU 内存访问违例 | `hw_sim` | 记录 `ResetRequired` 并中止当前提交；**复位路径仅第 36 章接入**（初级不产生 `ResetRequired`），且为引擎级复位（Q-30、Q-69） |
| 驱动层错误：KMD/HLI 传参非法 | `kmd` / `hli` | 返回业务 `Result` 错误码，**不触发设备复位** |
| 应用层输入错误：非法句柄、错误参数 | `umd` 层拦截校验 | 转换上层返回码，向下不传递非法参数给 KMD |

**红线**：应用逻辑错误不允许穿透直达硬件单元、触发 GPU 设备复位。

### 5.3 跨层错误传播契约

全栈跨层接口统一使用 `Result` 枚举，三条硬性规则：

1. `hw_sim` 硬件单元只返回硬件类错误码：`NotMapped` / `InvalidPacket` / `InvalidIsa` / `ResetRequired`，不做应用语义判断；
2. KMD/FW 转发硬件错误，追加内核层错误；
3. UMD 层做 API 参数校验，将底层 `Result` 转换为上层语义；**禁止吞掉硬件错误，必须向上层报告**。

**硬件边界禁止 C++ 异常**：异常只允许层内开发调试，跨层全部使用 `Result` 返回。

### 5.4 逻辑特权分层（高级 A：10 章落地，初级不实现）

真实 GPU 栈：Firmware 最高特权、KMD 内核态、UMD 用户态。软件不引入真正操作系统隔离，改用**逻辑特权标记**：

- `hw_sim` 硬件引擎接收提交时携带特权标记；
- UMD（用户态）不允许直接下发复位、修改页表根、看门狗等特权 MMIO 操作；特权操作必须经 KMD-DDI 封装，由 Firmware 执行。

价值：复现真实驱动安全模型，为未来虚拟化扩展预留。

### 5.5 HLI 对象双维度引用计数（35.1 高级）

解决经典 GPU 模拟器 bug：应用销毁资源句柄，GPU 还在 ring 上执行该资源，发生 use-after-free。HLI 对象（buffer / image / descriptorHeap / pipeline）采用双维度引用计数：

1. **用户引用计数**：应用调用 Destroy 时减少用户侧引用；
2. **硬件提交引用计数**：命令提交到 Ring 后硬件持有引用，fence 全部完成之后才释放硬件引用。

只有用户引用 **AND** 硬件提交引用都归 0，才真正释放 GPU 底层内存。初级没有 HLI，薄提交门面不需要引用计数。

### 5.6 扩展预留（计算、Mesh-Task、二期特性）

1. 命令包 `PKT_TYPE` 使用预留号扩展（当前顶层仅剩 `0x0F`，扩容方案见 `docs/design/bit-budget.md` §2），新增硬件命令不修改包头布局；
2. `IEngine` 引擎类型枚举预留未来硬件引擎；
3. `Capability` 能力查询作为唯一开关，二期功能只新增能力 bit，不修改核心数据结构与契约。

## 6. 确定性与双执行策略

| 项 | 初级 | 高级 |
|---|---|---|
| 执行策略 | 仅 `serial` 单线程 | `serial` / `parallel` 双策略（31 章落地） |
| 并行度配置 | 无 | `worker_threads`、`se_count`、`tile_w/tile_h` 可调 |
| 缓存/TLB 统计 | 无（无缓存模型） | 可开/关，只影响统计不影响结果 |
| 硬判据 | 全图逐字节 | 探针点 + query + 命令数/波数/图元数/像素写入数 + fence 顺序 |
| 软观测 | 无 | 耗时与加速比、命中率、每 SE 波分布 |
| 计算线 | 不覆盖 | dispatch 与图形共用同一确定性规则（S18/S19）；不因 workgroup 调度顺序改变结果 |

**时间无关（作用域澄清，两阶段共同）**：时间无关约束**作用于硬件路径与主机时钟**——硬件内部全部事件只依赖两类逻辑时间源：`frame_index`（帧序号）与 `timeline-semaphore / fence` 逻辑时间戳；`std::steady_clock` / 系统时钟**只用于性能耗时统计**，禁止参与硬件状态、着色器执行、内存判断、屏障逻辑。**着色器内可以使用按 `frame_index` 确定性推导的周期参数**（如旋转角、随时间推进的场景展示），`frame_index = n` 的画面必须等于"直接以 n 初始化"；场景展示按固定旋转角逐帧推进即可（不再为"与外部 GPU 对照"保留额外 uniform 约束，见 §12 #21）。禁止 `uTime` / `clock()` / 墙钟差值进入硬件状态或 CPU 位姿复算。

**确定性**（两阶段共同）：任何并行度、线程数、调度顺序下，硬判据必须一致；任何硬判据不一致一律先视为缺陷，而不是"并行正常波动"。

**内存别名与重排序**（两阶段共同）：硬件单元不会自动消除内存别名、不会自动插入屏障，严格按照内存序执行读写；多个资源 / UAV / 视图映射到同一物理内存产生的别名是未定义行为，**属于上层应用 / 驱动责任**；模拟器核心硬件路径不做全局别名检测（运行开销巨大），别名检测仅作为 tools 调试工具、可开关、不改变硬件执行结果。

**分配可复现**（两阶段共同）：所有随机行为绑定可复现伪随机种子，禁止直接调用主机全局 `rand()`；内存分配器 VA 序列必须可复现——初级 bump 天然可复现，高级 11 章堆管理器支持配置种子（§4.8.5）。

## 7. 校验模型演进

| 阶段 | 主判据 | 参照源 | 阻断策略 |
|---|---|---|---|
| 初级 | **全图逐字节**比对固定基线（PNG/字节数组） | 仓库内基线文件 | 一律阻断（不一致即失败） |
| 高级 | **固定探针点**比对（16~256 点/场景） | CPU 参考模型生成的探针期望值 | 一律阻断 |

高级阶段的全图逐字节默认只作可选调试导出 `--dump-all`；但**逐字节本身可作正式判据**——第 27 章 MSAA resolve 等确定性场景按逐字节阻断。容差口径全域统一：覆盖 ±1/16 子样本、颜色 ±2/通道、深度 ±1 LSB；所谓"像素零容差"只适用于 1x 覆盖率与 L1 结构/计数断言，不适用于浮点滤波后的颜色（Q-60）。

### 7.1 校验分层与参照归属

| 级别 | 参照源 | 判据强度 | 失败处理 | 是否进门禁 |
|---|---|---|---|---|
| L1 契约/结构 | 结构体/枚举断言、汇编往返、完成计数、fence 顺序 | 零容差 | 阻断 | 是 |
| L2 解析模型 | CPU 参考模型（像素中心、覆盖率、LOD、混合公式）+ 探针表点比对 | 明确容差 | 阻断 | 是 |
| 横切 | 串行/并行、多后端（HLI/Vulkan/D3D12/GL）、开关差分 | 零容差 | 阻断 | 是 |

- **参照源只使用 CPU 参考模型**：统一放 `tools/ref_model/`，场景程序与探针表生成共用；参考模型自身用"手算解析值"单测，不得拿模拟器输出自证。**不接入宿主真机 / 外部 GPU 渲染对照**，场景验收不依赖任何外部图形 API 或渲染后端。
- **容差集中管理**：默认容差写在 `tools/ref_model/tolerances.toml`，§7.2 的数值是默认值，可按场景覆盖；禁止把容差散落在场景代码里。
- **每章 DoD 必须声明所属级别**；场景文档（§7.4）的判定矩阵进一步区分阻断 / 告警 / 观测 / 人工四类。

### 7.2 高级探针模型

| 角色 | 产生者 | 用途 | 是否阻断 |
|---|---|---|---|
| 被测对象 | CPU 模拟器（渲染通路本身） | 输出探针点 / 全图 | — |
| 探针期望值 | `tools/ref_model`（解析计算或固定基线） | 探针表真值来源 | 是 |
| 探针表 | `tools/ref_model/probes/s<XX>_probes.txt` | 固定坐标 + 容差 | 是 |

- 探针表每场景一份，坐标用归一化 Q16（与 `rt_size` 解耦），固定顺序 `(y, x)` 升序，数量 16~256，必须覆盖前景内部、图元边缘、背景、纹理角点、被遮挡区；
- 探针表是**场景输入的一部分**，禁止运行期动态生成，改动需在章文档登记；
- **探针期望值来自模拟器自带的 CPU 参考模型（解析计算或固定基线）**，不在代码内硬编码、不由宿主真机渲染得到，因此不受厂商 GPU 在共享边 / 浮点舍入 / LOD 上的合法差异影响；
- 容差：颜色 ±2/通道、深度 ±1 LSB、覆盖率 ±1/16 子样本、计数/状态类为 0（不进探针表，直接用断言）；三处口径全章统一，不得再出现第二种覆盖容差（Q-60）；
- 探针表随渲染逻辑同步维护：任何改变像素输出的实现变更，必须在同一次提交内更新探针表，否则 CI 会持续失败。

### 7.3 配置项

| 键 | 取值 | 适用阶段 | 说明 |
|---|---|---|---|
| `exec_mode` | `serial` / `parallel` | 高级 | 默认 `serial` |
| `worker_threads` | `1..N` | 高级 | 默认 1 |
| `se_count` | `auto` / `1` / `2` / `4` / `8` | 高级 | `auto = min(hardware_concurrency, 4)`，CI 基线固定 1 |
| `warp_size` | 固定 32 | 两阶段 | 不开放配置，避免基线漂移 |
| `cache_enable` | `on` / `off` | 高级 | 只影响统计，不改变结果 |
| `rt_size` | `256x256` / `1080x720` / 自定义 | 两阶段 | 场景底板尺寸 |
| `api_backend` | `hli` / `vulkan` / `d3d12` / `gl` | 高级 | 默认 `hli`；硬判据必须一致（S17） |
| `trace` | `off` / `<unit>` | 两阶段 | 单步打印指定单元的输入输出（初级阶段的主要教学工具） |
| `dump_raw_output` | `off` / `on` | 两阶段 | 校验失败时自动导出原始 raw 帧，作为 CI 诊断制品 |
| `max_allowed_bad_pixels` | 0~8192 | 高级 | 全图掩码差分告警阈值，仅告警、不阻断门禁 |
| `kft_allow` | `off` / `on` | 高级 | 开启 Known-Failing-Test（KFT）警告输出 |
| `log_level` | `Error` / `Warn` / `Info` / `Debug` / `Trace` | 两阶段 | 运行日志输出等级；CI 只输出 `Error`/`Warn` |
| `hw_counters_enable` | `on` / `off` | 高级 | MMIO 只读硬件统计计数器开关；关闭零开销，仅软观测不阻断 |
| `mem_sanitizer` | `on` / `off` | 高级 | GPU 内存 Sanitizer（越界 / use-after-free / 未初始化读）；默认关，性能开销大，调试用 |
| `translation.seed` | u64 | 高级 | 页表 / TLB / 堆分配的确定性伪随机种子；同种子下 GPU VA 序列与 TLB 替换序完全一致（11 章） |
| `memory_budget` | 字节数 / `auto` | 高级 | GPU 地址空间预算上限；`auto` 按堆类型取默认值，超限返回 `OutOfMemory`（11、14 章） |
| `simd_per_cu` | `1` / `2` / `4` | 高级 | 每 CU 的 SIMD 数量；只影响波调度分布与软观测，不改变硬判据（15、31 章） |
| `tile_w` | 正整数，≤ `rt_size` 宽 | 高级 | SE 光栅化 tile 宽（像素），默认 4；仅 `exec_mode=parallel` 生效 |
| `tile_h` | 正整数，≤ `rt_size` 高 | 高级 | SE 光栅化 tile 高（像素），默认 4；仅 `exec_mode=parallel` 生效 |

- `tile_w` / `tile_h` 只决定第 31 章 SE 屏幕分块粒度与负载统计，不改变像素/探针结果；与第 25 章固定的 **2×2 quad** 是不同概念，quad 尺寸不开放配置（导数语义依赖它）。
- 默认 2×2 在 1080p 下约 51.8 万个 tile，仅建议小分辨率/功能验证使用；较大 RT 建议 8×8 或 16×16，任何取值都必须保持像素结果不变。
- 屏幕边缘不足一个 tile 时按部分 tile 处理：`tilesX = ceil(rt_width/tile_w)`、`tilesY = ceil(rt_height/tile_h)`；任何取值都必须满足 D31.2（tile 并集=全屏、互不重叠）。

### 7.4 测试场景规约（单份场景文档）

E0~E5 / S0~S19 的**完整测试规约**不在本文件展开，统一写入单份 `docs/scene-specs.md`（**不建 `docs/scene-specs/` 目录**，Q-38）：

- 单文件内每个场景一节（`Exx` / `Sxx`），沿用下列固定十节模板；§3.5、§4.5 的精简概览表保留供快速查阅，完整规约以该单文件为准；`graphics/test-cases.md` 降为历史参考，其数值按 warp32 重算后并入该文件（Q-40）。
- **统一模板（固定十节）**：元信息（场景ID / 程序入口 / 阶段 / 关联章节 / KFT 标记 / spec 版本 / 变更 ADR）、前置条件（硬件配置 + 功能前置 + 环境约束）、输入集合（固定输入 + 子 case 可变参数）、标准化执行步骤、输出产物集合、判定矩阵、子 case 列表、退出条件、回归矩阵、引用。
- **判定矩阵四分类，每项含容差与失败行为**：
  - **阻断门禁**：不满足即 CI 失败（初级 E：全图逐字节 + L1/L2 断言；高级 S：探针表 L2 为阻断门禁，全图差分仅告警）；
  - **仅告警**：输出差分图等，不阻断；
  - **纯观测统计**：wave 数、缓存命中率等，仅日志；
  - **仅人工检视**：窗口可视化画面，不参与自动化 CI。
- **支持子 case**：同一个二进制跑多组输入（case-0 … case-N），复用同一套探针与判据体系；**KFT 标记**绑定到子 case（如 `case-2:MeshTask(ADR-xx)`，二期未实现能力），命中只输出警告、不计入失败。
- **输入永久冻结**（初级 E）：spec 输入集合明确标注"输入永久冻结，修改必须 ADR"；几何、纹理、背景值不得改动，只能改探针容差。
- **产物入库规则**：spec 文档、探针文本表、初级 E 的 `.raw` 基线 **git 入库**；PNG、差分图、trace 日志为 CI 临时产物、不入库。
- **回归矩阵**：写明该场景必须遍历的配置组合（`exec_mode` / `cache_enable` / `se_count` …），不是所有场景都跑全组合。
- **高级 S 双轨校验**：阻断门禁保持 L1 契约断言 + L2 探针点比对（期望值 `tools/ref_model` 解析模型实时生成）；另增加**非阻断全图掩码差分（仅告警）**，阈值由 `max_allowed_bad_pixels` 配置，超过阈值输出告警与差分 PNG、不阻断 CI——用于捕捉"错误区域恰好没有探针点"的大片漏检缺陷；**严禁把全图差分升级为阻断门禁**（并行与浮点滤波会产生少量像素噪声，会造成 CI 抖动）。
- **基线存储规则**：初级 E 校验基线是原始 BGRA `.raw` 二进制，git 入库；PNG 仅人工查看、不作为校验真值；**高级 S 不存储任何完整图像基线**，期望值运行时由 `ref_model` 解析模型生成，仓库只存探针文本表；禁止大尺寸 PNG 进入 git。
- **CI 失败诊断产物**：任一校验失败自动产出制品包并上传：① 模拟器输出 `.raw` 帧；② `ref_model` 期望 `.raw` 帧；③ 差分放大 PNG（坏像素高亮）；④ CSV 探针完整报告（坐标 / 期望 / 实际 / 差值 / 是否超限）；⑤ 场景配置快照 JSON（`exec_mode` / `se_count` / `cache_enable` / `rt_size` 等）；⑥ 对应场景 `--trace` 日志。全部 headless 可用、不依赖窗口。
- **KFT 绑定**：二期未实现能力可标记整个场景或部分探针点为 KFT，绑定 issue 编号；`kft_allow=on` 时 CI 统计并输出警告、**不阻断门禁**；禁止直接注释或删除测试用例，功能实现后移除标记。
- **CI 回归矩阵**：编译器 MSVC / GCC / Clang × `exec_mode ∈ {serial, parallel}` × `cache_enable ∈ {on, off}`；初级 E0~E5 全字节校验**强制关闭 `-ffast-math`**（否则跨编译器字节不一致），高级 S 不依赖全字节、允许浮点优化。

**场景文档是冻结契约**：修改场景输入、探针集合、阻断判据、KFT 绑定，必须走 §10.3 契约变更工作流（新建 ADR）；`apps/scene_*` 严格对齐 `docs/scene-specs.md` 对应节，不得私自修改输入参数。

### 7.5 窗口与 Headless 约束

窗口系统属于**上层调试工具**，不属于虚拟 GPU 硬件单元；初级 1~9 不强制窗口，只导出 `.raw` / PNG；窗口作为高级 E 阶段的可选开发工具实现。三条铁律：

1. **模拟器渲染源头永远是 CPU 内存帧缓冲**：`uint8_t` BGRA 原始缓冲区，内存序与全栈统一（ADR-015）；`hw_sim` / firmware / kmd / hli **完全不知道窗口、SDL、GLFW 的存在**。
2. **窗口只做位图显示**：窗口适配层放 `umd/os`，仅把 CPU 内存块上传宿主 GPU 纹理并全屏 blit；**宿主 GPU 严禁参与任何渲染、光栅、着色计算**，只作为位图显示器。窗口渲染输出绝不作为真值来源。
3. **窗口与模拟器逻辑解耦**：`rt_size` 是模拟器硬件逻辑分辨率、不随窗口缩放改变，窗口任意缩放只是双线性/近邻展示；`frame_index` 完全由应用提交驱动，**禁止窗口 vsync / 操作系统时钟驱动模拟器帧逻辑**（严格遵守时间无关约束）；窗口 vsync 只控制画面多久刷新到屏幕，不改变渲染输出。

**headless（CI）约束**：自动化校验完全不依赖窗口库，CI 可在无显示器 headless 环境跑全部 E/S 回归；CMake 开关 `BUILD_WITH_WINDOW=ON/OFF` 关闭窗口依赖时，`tools/ref_model`、`tools/image_diff`、探针校验工具与批量回归脚本仍然完整编译。所有校验读取 CPU 内存原始缓冲区，绝不读取窗口后端帧。

**窗口功能清单（全部是软件后处理可视化，不参与任何自动化判据）**：

- 模式 `headless` / `windowed`；保存当前帧为 `.raw`（校验用，优先）与 PNG（人眼查看）；重放当前场景。
- 鼠标探针拾取：窗口坐标 → 模拟器归一化 Q16 探针坐标，控制台打印 `(x,y) | RGBA | 深度值 | coverage 子样本掩码 | primitiveID | waveID | 所在 SE 编号`（headless 等价物 `tools/pick_probe`）。
- 多调试视图切换（对 CPU 输出缓冲区做后处理，不改动模拟器硬件输出）：原始颜色 / 深度热力图 / Coverage 伪彩 / WaveID 伪彩（观察 SE 分区与并行调度）/ Hi-Z 拒绝可视化。
- 帧 dump：一键导出离线 JSON（场景参数快照、全部生成图元列表、wave 统计、全部探针点结果、硬件统计如缓存命中率与 fence 值），可离线分析、不需要重跑模拟器。

**实现阶段**：初级（1~9）不做窗口，只保证 raw / PNG 导出与 headless E0~E5 校验；高级 A~D（10~31）先做 `tools/ref_model`/`image_diff`、探针体系、全图差分告警、CI 诊断产物，跑通 S0~S11 自动化校验；高级 E（32~36）再实现窗口可视化交互工具。自动化校验优先跑通、窗口可视化放后，避免"为看画面而开发但校验跟不上"。

### 7.6 日志、硬件统计与断言

**普通运行日志 `GD_LOG`（初级实现，ADR-010）**：等级 `Error / Warn / Info / Debug / Trace`，统一格式 `[level][module][submodule] msg k1=val1 k2=val2`，纯 ASCII。

- 热点路径（逐像素 / 逐 wave 循环）严禁打 Debug/Trace 日志；
- **输出分层**：不同模块的中间日志写入对应文件，控制台只展示各模块核心日志与错误日志（`log_level` 控制），借鉴既有日志系统设计；
- CI 环境只输出 `Error/Warn`；Debug/Trace 编译期可裁剪。

**硬件统计计数器（高级 A，MMIO 只读）**：wave 执行数、cache 命中 / 失效、图元数、barrier 执行次数等硬件内部累加统计，经 MMIO 寄存器读取；`hw_counters_enable` 开关，关闭零开销；仅软观测，不参与门禁阻断。

**断言三套体系**：

1. 编译期 `static_assert`：用于契约、结构体、枚举；
2. 开发期 `DEV_ASSERT()`：Release 编译直接移除，只检查内部不变量；
3. 硬件行为校验：Release/Debug 都执行，不直接 abort，返回 `Result` 错误码进入日志并中止当前提交；复位路径仅第 36 章接入（引擎级）。

**红线**：不要用原生 `assert()` 做硬件正确性校验——Release 版本硬件违例不能直接进程崩溃；初级只记录错误码 + 中止提交、不产生 `ResetRequired`，复位行为统一由第 36 章按引擎粒度实现（Q-30、Q-69）。

> 结构化硬件 trace（json-line）**不纳入开发范围**（按批注）；`--trace` 维持仅人工、不做机器解析契约（§9）。所有日志 / trace / 计数器都只是调试手段，**CI 校验只信任探针 + `ref_model`**，绝不把日志输出当作正确性判定。

## 8. 能力边界（四档）

每项能力必须归入以下一档，不得留空；高级二期项必须在 HLI 暴露 capability bit，一期调用返回"不支持"而不是静默降级。

35.1 的 `Capability` 枚举必须显式包含二期四位（Task/Mesh Shader、Multiview、Conservative Rasterization、设备丢失/TDR/抢占），一期恒 `false`，UMD 与计算驱动只读 HLI 能力位、不得自行映射（Q-72）。

### 8.1 初级范围（1~9 章，必须实现，不许降级）

- §3.2 全部 9 章 + E0~E5 场景；
- 一条完整通路：提交 → 取命令 → 地址 → 顶点 → 着色器 → 固定功能管线 → 纹理 → 输出上屏；
- 仅串行、单上下文、单队列、单 RT。

### 8.2 高级一期（P0，纳入实现）

- 10~34、36 全部硬件章节与 P0 功能补强项：全阶段 UAV、Bindless、视图分离、管线对象、push constant、屏障与所有权转移、独立 DMA 引擎、Early-Z/Hi-Z/fast clear、数组/Cubemap、独立采样器、插值修饰符全集、点线光栅、LoadOp/StoreOp、双源混合、内存序映射、三维 workgroup、GPU 侧谓词、完整 Tess/GS、多视口；
- 计算线：kernel 对象与参数缓冲（20）、workgroup 三维映射（31）、修复作用域内存序（30）、间接 dispatch（33）、异步计算与计算/图形互操作（32）、计算统计（34）；
- 必须覆盖的功能缺口：**实例化渲染**（`baseVertex`/`baseInstance`/`InstanceID`，22）、**Clip/Cull Distance**（24）、**PS 输出到 RT 存储格式转换**（UNORM/SNORM/UINT/SINT/sRGB，26）、**命令包版本号**（1、10；高级 `STREAM_HEADER.version=2` 并拒绝 v1）、**标准化能力查询接口**（35.1）、**描述符堆设备内存更新语义**（20）、**动态状态命令缓冲快照语义**（35.1）；
- 35.1 HLI（图形 + 计算共用包格式）+ 35.2 Vulkan-UMD + 35.3 D3D12-UMD + 35.4 OpenGL-UMD 核心子集 + 35.5 计算驱动（MUSA 对象模型，非 API 兼容）；
- S0~S19 高级场景 + 校验工具链 `tools/{ref_model, image_diff, pick_probe, scene_snapshot, spec_runner, log_analyze, mem_audit}` + 完整场景规约单份 `docs/scene-specs.md`（§4.9、§7.4）；窗口可视化工具高级 E 阶段可选（§7.5）。

### 8.3 高级二期（只留 capability bit，一期不实现逻辑）

| 能力 | 一期行为 | 二期内容 |
|---|---|---|
| Task / Mesh Shader | 能力位 false，创建即报"不支持" | 按 S15 二期判据验收；模型轮廓：不再依赖传统 IA，光栅输入来自 Mesh 输出图元 |
| Multiview | 同上 | 多视图实例化 |
| Conservative Rasterization | 同上 | 保守光栅 |
| 设备丢失 / TDR / GPU 抢占 | 只做 36 章的定位与复位 | 完整抢占与恢复 |

### 8.4 项目范围外（永不实现）

- 稀疏资源 / 虚拟纹理（页错误路径只服务驻留，不构成 sparse 绑定模型）；
- Vulkan RenderPass / subpass 对象模型（只建模 LoadOp/StoreOp）；
- BC 等压缩纹理格式（只做未压缩基础格式）；
- 可变 subgroup size、自定义 lane swizzle（固定 warp32，lane 顺序即线性顺序）；
- 视频编解码硬件引擎；
- SR-IOV / MIG / GPU 虚拟化 / 多进程共享；
- 电源、频率、热管理；
- 周期精确时序、总线时序、DRAM 时序、带宽与绝对性能建模；
- 真实指令周期与流水线级延迟（只做功能级停顿）；
- 硬件级 ECC、可靠性、容错重试；
- 具体游戏引擎或资产管线（只保留最小场景作为验收载体）；
- 细粒度页错误恢复（wave 暂停 / 恢复）：不建模暂停-恢复；复位由第 36 章按引擎级接入，不做设备级重启（11、14、36，Q-69）；
- MUSA / CUDA 的 API 或二进制兼容：只借鉴对象模型与调用路径（35.5）；
- Mesa 代码级复用或内部接口兼容：只借鉴分层、对象生命周期与 IR 形状（35.1、17）；
- 屏障的逐访问位掩码：一期只做 READ / WRITE / ATTACHMENT / TRANSFER 粗粒度集合，不做 per-resource 位图（20、32，登记为简化）。

## 9. 横向关注点（每章都要交代）

| 关注点 | 要求 |
|---|---|
| 确定性 | 该单元引入的遍历/分配/并发必须确定序或确定归约；两种策略下硬判据一致 |

| 计算兼容 | 该单元在计算通路上是否有对应语义；共用单元不得为图形或计算任一方向特化 |
| 配置与回退 | 该单元能否关闭以回到简化基线 |
| 调试钩子 | shader printf / wave trace 只在显式开关下输出，不进入硬判据 |

| 契约变更 | 是否改动冻结契约；改动必须走 §10.3 工作流并回归 E0~E5 与受影响 S 场景 |
| 校验归属 | 该单元在哪些探针/断言上、按什么容差验收；探针表改动需登记 |

### 10.3 契约变更工作流

冻结契约范围：

1. 初级契约 `stage1/01-contracts-min.md`；
2. 高级 HLI 命令包格式与 HLI 对象接口（35.1）；
3. 场景输入：E0~E5 的几何/纹理/配置（**永久冻结**，只能改探针容差）、S0~S19 的探针集与阻断判据；
4. 场景规约：`docs/scene-specs.md` 的输入集合、探针集合、阻断判据与 KFT 绑定（§7.4）。

变更流程（缺一步不允许合并）：

1. 新建 ADR，写明背景、备选方案、最终决策、受影响章节；
2. 更新契约文档；
3. 更新所有受影响场景的 DoD 与判据；
4. 回归 E0~E5 + 受影响 S 场景（含 `serial`/`parallel` 双策略）；
5. 评审通过后合并。

ADR 规范：存放在 `docs/adr/ADR-<三位序号>-<kebab-title>.md`，必须包含背景、选项、决策、影响章节、测试与回归范围、回滚方式。

禁止项：改契约不改判据；35.1 冻结后 UMD 阶段反向修改 HLI；为通过测试而修改探针期望值。
