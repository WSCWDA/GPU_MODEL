### 0.4 异常处理简化（ADR-011）

- **只处理一般错误**：非法 VA、非法包类型/长度、ISA 解码失败、越界绑定等"能定位到单元 + 位置"的问题。
- **最小手段**：接口返回 `Result` + 一条错误日志 + 一条错误记录 `{unit, packetType, dwordOffset, va, code}`；不做重试、不做全链路错误传播、不做自动恢复。
- **崩溃即停**：错误路径打印后中止当前提交（返回错误码或 `assert`），不设计"错误 → 中断 → KMD → UMD → App 恢复"通路；**初级不产生 `ResetRequired`**。
- **与第 36 章的关系**：第 36 章只做到"故障可定位 + reset 后可重跑"，不扩展到容错运行；复位为**引擎级**（仅重编程该 ring），不做设备级重启（详见 `docs/design/boot-reset.md`）。

### 0.5 能力四档（ADR-025）

| 档 | 内容 | 处理 |
|---|---|---|
| 初级实现 | 1~9 章 + E0~E5 | 必须实现，不许降级 |
| 高级一期（P0） | 10~34、36 章与列出的功能补强项；35.1~35.4 与 37（计算管线收口） | 纳入实现 |
| 高级二期 | Task/Mesh Shader、Multiview、Conservative Raster、完整抢占与 TDR | 只留 capability bit，一期返回"不支持" |

### 0.6 计算线兼容原则

计算线整体在高级阶段引入，但兼容性在图形线推进中就必须付清：

1. 分层不为图形特化：`IShaderArray`、内存、缓存、队列、fence、描述符、查询均为 workload 无关。
2. 第 1 章冻结 `Stage::Compute`、`ThreadIdSpace`、`DispatchArgs`，即使暂时无人消费。
3. 第 20 章描述符同一套支持 SRV/UAV/CBV/Sampler，并为 kernel 参数缓冲预留绑定方式。
4. 第 32、33 章队列与 IB 不区分 draw/dispatch，间接与 predication 对两者同构。
5. 第 4、15、29、30、31 章的 SIMT、分歧、subgroup、shared/atomic 不得假设"只有一个 PS 阶段"。
6. 共用单元只能按包类型派发，不得出现"图形专用/计算专用"分支。

> 计算线的完整模块设计见 `docs/design/compute-line.md`；开发任务以独立第 37 章收口（ADR-013 修订），图形线预留点见 §6.1、启动条件与验收见 §6.3。

### 0.7 硬件行为原则（FPGA 视角）

模拟定位是"类似于 FPGA 的工作"：除功能正确外，以下行为特征作为全项目统一的实现原则，各落实为 ADR 并在对应章内以子里程碑落地。它们回答的是"GPU 为什么这么设计"（深流水线、延迟隐藏、标量/向量分工、occupancy），不是单纯的功能堆叠。

| 原则 | 内容 | 落点 |
|---|---|---|
| 功能级流水线与背压 | 单元间以输入 FIFO + 输出 FIFO + valid/ready 握手连接；下游忙（FIFO 满）则反压上游停发；多图元 / 多波可同时在不同阶段流动（不做周期精确） | ADR-035；第 4、10、23、25 章 |
| 延迟隐藏 | 高延迟操作（纹理采样等）异步化：波挂起 → 让出执行资源给就绪波 → 结果返回唤醒；这是理解 SIMT 调度动机的前提 | ADR-036；第 15、21 章 |
| 标量 / 向量分区 | ISA 层面区分标量指令与向量指令，SGPR / VGPR 独立编号空间，波内一致值走标量通路；现在定死编码，后期加计算不返工 | ADR-034；第 5、16、17 章 |
| MMIO 唯一硬件接口 | 一切配置、状态、统计只经 MMIO 寄存器读写，单元内部成员私有；接口与实现解耦，调试工具只依赖 MMIO | ADR-037；第 2、10 章 |
| 硬件资源上限 | 资源容量物理固定（驻留 wave / SGPR / VGPR / LDS / FIFO / 描述符堆），超限排队等释放，模拟真实 occupancy 限制 | ADR-038；第 31 章 |
| 状态机实现单元 | 单元核心逻辑用有限状态机（FSM）而非过程式代码，如 CP：空闲 → 取包头 → 解析 → 派发 → 写 fence → 空闲 | 第 2、10、21 章起 |

> 各原则机制细节的模块设计见 `docs/design/{execution-parallel, memory-system, isa-abi, command-mmio}.md`。

### 2.4 任务拆分模板（四段式）

每一章的任务按同一顺序展开：

| 段 | 任务 | 完成标志 | 数量 |
|---|---|---|---|
| ① 契约落地 | `T<x>.1` | 该章与上下游的数据契约写成头文件/枚举/断言并可编译；上下游各有一个最小用例 | 1 |
| ② 主体实现 | `T<x>.2 … T<x>.(n-2)` | 每个任务 = 单元内一个可单独断言的能力（一次命中、一次失效、一次边界、一条状态机转移） | 体量 − 3 |
| ③ 端到端接入 | `T<x>.(n-1)` | 该单元接入场景入口，命令链从场景/HLI 到该单元不断链 | 1 |
| ④ 场景验收 | `T<x>.n` | `A<x>` 全绿（场景主判据 + 专有判据 + 回归） | 1 |

**粒度上限**：单任务 ≤ 2 人日；超过则继续拆。主体实现超过 13 个任务时，先检查是否该拆章；少于 4 个时，检查是否该并入邻章。第 35 章按四个子里程碑（35.1~35.4）分别套用四段式；原 35.5 计算驱动已迁出（第 37 章 + stage3 38~42，ADR-013 修订/ADR-047）。

### 2.9 测试场景规约（单份场景文档）

E0~E5 / S0~S19 的完整规约集中在**单份 `docs/design/scene-specs.md`**（不建 `docs/scene-specs/` 目录），文件内每场景一节（`Exx_` / `Sxx_` 小节）。模块设计见 `../docs/design/validation-model.md`，本节只落任务与验收相关约束：

- **场景文档是冻结契约**：修改场景输入、探针集、阻断判据、KFT 绑定，必须走 §7.4 契约变更工作流（新建 ADR）；`apps/scene_*` 严格对齐该文件对应节，不得私自修改输入参数。
- **判定四分类** 阻断门禁（CI 失败）/ 仅告警 / 纯观测统计 / 仅人工检视；每项含容差与失败行为，写入对应场景的判定矩阵。
- **初级 E 输入永久冻结**：只能改探针容差，几何/纹理/背景值不得改动；高级 S 的探针表 L2 为阻断门禁，全图差分仅告警。
- **子 case 与 KFT**：同一个二进制跑多组输入（case-0 … case-N），复用同一套探针与判据；二期未实现能力绑定为 KFT 子 case，CI 命中只告警、不计入失败。
- **入库规则**：spec 文档、探针文本表、初级 E 的 `.raw` 基线入库；PNG、差分图、trace 日志为 CI 临时产物、不入库。
- **参照源只有 CPU 参考模型**（`tools/ref_model` / `../docs/design/validation-model.md`），不做真机/外部 GPU 参照渲染；验收不依赖任何外部图形 API 或渲染后端（ADR-027）。
- **高级 S 双轨校验**：L1/L2 探针保持阻断门禁；另加**非阻断全图掩码差分（仅告警）**，阈值 `max_allowed_bad_pixels`，捕捉无探针区的大片缺陷；严禁升级为阻断门禁（并行/浮点噪声会造成 CI 抖动）。
- **基线存储**：高级 S 不存任何图像基线，期望值运行时由 `ref_model` 生成，仓库只存探针文本表；PNG 不入库；初级 E `.raw` 基线入库（`docs/design/scene-specs.md` §1.4）。
- **CI 诊断与矩阵**：校验失败自动产出 6 类诊断制品（输出 raw / 期望 raw / 差分 PNG / CSV 探针报告 / 配置快照 JSON / `--trace` 日志）；CI 矩阵 = 编译器(MSVC/GCC/Clang) × `exec_mode` × `cache_enable`；初级全字节校验禁 `-ffast-math`。
- **KFT 绑定 issue**：场景或探针点可标记 KFT 并绑定 issue 编号，`kft_allow=on` 输出警告不阻断门禁；禁止直接注释/删除测试，功能实现后移除标记。
- **窗口与 headless 解耦**：窗口是高级 E 阶段可选调试工具（放 `umd/os`，只做 CPU 帧 → 宿主 GPU blit），不参与渲染计算；`frame_index` 由提交驱动、禁 vsync/墙钟；校验不依赖窗口，headless 可完整跑全部 E/S（`docs/design/validation-model.md` §8，构建开关 `BUILD_WITH_WINDOW`）。

## 3. 执行顺序与串行原则

### 3.1 串行推进（ADR-014）

1. **任务级**：`T<x>.n` 的 `D<x>.n` 全部勾选后才开下一条任务；同一章内也不并行。
2. **章级**：`A<x>` 全绿（场景主判据 + 专有判据 + 回归）后才开下一章；不允许"先写代码后补验收"。
3. **阶段级**：§2.3 三列门禁全绿后才进入下一阶段。
4. **不设并行分支**：单人串行开发；需要试错时在当章内用临时分支，合回即删。
5. **契约先行**：任何跨章契约变更，先改 ADR 与架构文档，再改代码。

### 3.2 允许交换的顺序对

以下交换不改章号、不改任务编号，只调整推进先后：

| 可交换 | 条件 | 理由 |
|---|---|---|
| 19 ↔ 20 | 第 18 章完成后 | LLVM 对照与资源绑定无数据依赖；19 完成后必须立刻回收，避免双后端长期并存 |
| 34 提前到 31 之后 | 第 31 章完成 | 查询可复用并行阶段的波/像素计数，早做能更早暴露统计口径问题 |

> **12 与 14 不可交换**：第 14 章逐出前必须调用第 12 章 `CacheSubsystem` 完成 flush，依赖单向（Q-47）。

### 3.3 章号顺序的例外说明

- **4/15 与 5/16**：初级第 4、5 章用"内存内指令结构 + 语义"实现执行与最小 ISA；高级第 15、16 章才补齐分歧、控制流栈与完整二进制编码。初级验收看"语义与寄存器终态"，高级验收看"往返二进制一致"。
- **17、18、19**：第 18 章必须先把手写后端定稿（含寄存器分配与发射），第 19 章才能以"逐字节一致"作为唯一判据；19 未过不进入 20，否则后端缺陷会被数据通路掩盖。
- **20 与 16**：资源与绑定依赖 ISA/ABI 冻结，但可以先于几何前端实现；第 21 章纹理接在其后。
- **35 与 20~34**：API 后端必须在 HLI 接口面稳定后做映射；35 只做对象模型与语义映射，不引入新硬件能力。35.1 先行冻结包格式；计算驱动由第 37 章收口、stage3 38~42 承载实现（ADR-013/047）。
- **36 贯穿全程**：10~35 各章在实现时保留错误码与"单元 + 包类型 + dword 偏移"定位钩子；第 36 章最后统一收口 watchdog、复位与故障注入，不把错误处理推迟到 36 才从零补。

### 3.4 启动禁令

| 禁令 | 原因 | 解除章 |
|---|---|---|
| 第 3 章完成前不引入任何并发 | 没有统一地址空间，并发只会把 bug 藏起来 | 3 |

### 3.5 初级爬升纪律

严格线性，不允许跳章：

```
1 契约最小集 → 2 设备与单环 → 3 平坦内存 → 4 SIMT 单波 → 5 最小 ISA
→ 6 固定功能最小集 → 7 纹理最小集 → 8 帧输出 → 9 端到端验收
```

第 4 章前不能执行任何着色器，第 6 章前不能产生任何像素，第 8 章前不能看到画面。初级每条简化假设必须能在代码中定位到唯一实现点，便于高级替换。

| `log_level` | `Error`/`Warn`/`Info`/`Debug`/`Trace` | `Warn` | 日志等级；CI 只 `Error`/`Warn`，Debug/Trace 编译期可裁剪 |
| `hw_counters_enable` | `on`/`off` | `off` | MMIO 只读硬件统计计数器；仅软观测不阻断 |
| `mem_sanitizer` | `on`/`off` | `off` | GPU 内存 Sanitizer（越界/UAF/未初始化读）；默认关，调试用 |
| `translation.seed` | u64 | — | 页表 / TLB / 堆分配的确定性伪随机种子；同种子下 GPU VA 序列与 TLB 替换序完全一致（11 章） |
| `memory_budget` | 字节数 / `auto` | `auto` | GPU 地址空间预算上限；`auto` 按堆类型取默认值，超限返回 `OutOfMemory`（11、14 章） |
| `simd_per_cu` | `1` / `2` / `4` | 1 | 每 CU 的 SIMD 数量；只影响波调度分布与软观测，不改变硬判据（15、31 章） |

- `tile_w` / `tile_h` 只决定第 31 章 SE 屏幕分块粒度与负载统计，不改变像素 / 探针结果；任何取值都必须保持像素结果不变（屏幕边缘按部分 tile 处理：`tilesX = ceil(rt_width/tile_w)`、`tilesY = ceil(rt_height/tile_h)`）。

### 5.2 两种策略

| | 策略 A：确定性串行 | 策略 B：硬件对齐并行 |
|---|---|---|
| 线程 | 单线程 | N 个工作线程（与 `se_count` 独立配置） |
| 波领取 | 固定顺序 | CU 内原子领取 |
| 图元/像素顺序 | 固定 | SE 屏幕 tile 静态分区，区内确定 |
| 内存 | 单一 TLB 视图 | 线程本地 TLB + 全局失效 |
| 用途 | 黄金基线、问题定位 | 观察并行行为、性能差异、竞争缺陷 |

### 5.3 各章与策略的关系

| 章 | 与双策略的关系 |
|---|---|
| 1 | 冻结配置键与"硬判据/软观测"定义，不实现策略 B |
| 2、10 | 环与 CP 在策略 B 下仍是单点消费，包序不被多线程打乱 |
| 3、11 | 地址翻译必须线程安全或明确"仅单线程"，为 31 章留扩展点 |
| 4、15 | 波执行与分歧轨迹在策略 A 下确定；策略 B 下同波结果不变 |
| 12 | `cache_enable` 开关前后逐字节一致；S11 只跑 `se_count=1` 的退化子集 |
| 13 | Display 只在提交完成后读 RT，不与执行并发 |
| 14 | 两上下文互不污染在两种策略下都必须成立 |
| 22、23 | 切片粒度与 `worker_threads` 解耦：切片数由容量决定，线程数只决定谁执行 |
| 29、30 | 归约/原子必须定义归约顺序；barrier 不得依赖线程到达顺序 |
| 31 | 实现策略 B：线程池、SE tile 静态分区、CU 原子领取、线程本地 TLB + 全局失效 |
| 32、33 | 多队列依赖顺序由 fence/semaphore 定义，不得依赖线程调度 |
| 34 | 查询归约顺序固定；timestamp 只做单调性判定 |
| 35 | 直连 HLI、三套 UMD 在两种策略下输出一致；UMD 不改写 HLI 包 |
| 36 | 故障注入在两种策略下都能定位到单元与位置 |
| 37 | 计算线 S18/S19 在两种策略下零容差一致；计算驱动入口与直连 HLI 入口等价 |
| 38~42 | stage3 计算驱动：S18/S19 经计算驱动入口与直连 HLI 入口逐值等价；同一 kernel 在 `serial`/`parallel` 探针零容差一致 |

### 5.4 判据与回归矩阵

计算线场景（S18/S19）在 37 章前不做端到端主判据（29~34 共用单元只做能力验证）；第 37 章先以直连 HLI 计算入口跑通，再经计算驱动入口双跑等价后作为主验收；不为计算线新增配置键（入口选择复用 `api_backend = hli / compute`）。

- **硬判据（必须一致）**：探针点颜色/深度/覆盖率、query 数值、命令数、波数、图元数、像素写入数、fence 语义顺序。
- **软观测（允许不同，只记录）**：墙钟耗时与加速比、缓存 / TLB / I-Cache 命中率、每 SE 波分布、每线程负载、每级 FIFO 平均占用率与反压周期计数、波切换次数、非探针像素。
- **双策略**：`serial` 与 `parallel` 在探针点上必须**零容差**一致；参照源为 CPU 参考模型，容差集中管理于 `tools/ref_model/tolerances.toml`。
- **全图逐字节**：初级作为主判据；高级只保留 `--dump-all` 调试导出。
- **31 章之前**：`exec_mode=parallel` 必须显式报"策略 B 未实现"，**不得静默退化为串行**。
- **31 章之后**：S11 必须覆盖 `se_count ∈ {1,2,4,8} × worker_threads ∈ {1,2,4}` 的可用组合；任一硬判据不一致，先按正确性缺陷处理。
- **校验失败的工具行为（`spec_runner` 契约，与 `docs/design/scene-specs.md` §1 一致）**：对回归矩阵**逐配置独立判定**，任一组合失败即如实上报并阻断门禁，**禁止自动降级 / 回退配置**——不得把 parallel 失败静默改跑 serial 掩盖、不得缩小矩阵、不得把失败当 KFT/告警吞掉；31 章前 `exec_mode=parallel` 必须显式报"策略 B 未实现"，设置失败与校验失败两类都显式报错。任一失败产出 `docs/design/scene-specs.md` §1.5 的六件套诊断制品。

### 5.5 确定性规则

1. **无时间输入**：着色器 uniform 与 CPU 位姿计算禁止 `uTime`、`clock()`、墙钟差值。
2. **位姿可复算**：只由 `(scene_id, frame_index, camera_params, model_matrix)` 决定；`frame_index = n` 与"直接以 n 初始化"必须一致。
3. **遍历顺序固定**：图元、像素、描述符、资源的遍历顺序显式定义；并行时按 tile/wave 分区并固定区内顺序。
4. **归约顺序固定**：`ballot/shuffle/atomic add` 的归约顺序写死（按 lane 升序或原子累加），不得依赖线程完成顺序。
5. **无未定序随机**：扰动使用固定种子且消费顺序固定，禁止每线程各自取随机数。
6. **平局可判**：深度相等、时间戳相等、稳定排序必须给出确定 tie-break（如按 primitive id）。
7. **内存序显式**：原子与屏障使用 `Relaxed / Acquire / Release / AcqRel / SequentiallyConsistent`，作用域区分 `Workgroup / Device`；shared 栅栏与全局资源屏障是两套机制。

### 6.2 计算线最小通路

计算最小通路（kernel → module/function → 参数缓冲 → dispatch → workgroup/CU → wave → LDS/原子/barrier → 写回 → fence/查询）与"三点本质差异"（无 IA/光栅/OM、workgroup 是调度单位/wave 是执行单位、内存作用域与 barrier 是正确性核心）见 `docs/design/compute-line.md` §1，本文件不再重复。

### 6.3 启动条件与验收

- 启动条件：第 20 章绑定接口与 `KernelArgsLayout` 契约、第 29~31 章共用执行单元（subgroup/shared/atomic/barrier/occupancy/三维映射）稳定、第 32~34 章队列/IB/查询稳定、35.1 HLI 冻结后；stage3 38 章计算驱动在 37 章计算入口收口之后实现（遵守 35.1 DoD 全绿纪律，不反向修改 HLI 接口）。

- 收口章：**计算管线**（参数打包、Compute 派发、调度收口、异步计算、间接派发、统计）在第 37 章收口；**计算驱动对象模型与双入口验收**归 stage3 38~42（ADR-047/048，2026-11-20 修订 D2）。不再由 20/29~31/33/35.5 各章承载端到端验收判据。

### 6.4 驱动分层借鉴

Mesa（图形）与 MUSA（计算）分层借鉴的对应表见 `docs/design/compute-line.md` §2；只借鉴分层、对象生命周期与 IR 形状，不引入 Mesa / MUSA 代码。

| dispatch 形式 | 直接 / 间接 | 逐值等价 |
| 队列形态 | 单队列 / compute 队列 + 图形队列并行 | 硬判据一致，顺序只由 fence 定义 |

**配置口径**：计算线**不新增配置键**（§5.4）；`DispatchDesc` 的取值由场景子 case 携带，不进 §5.1 配置表；`kMaxWorkgroups` 与 CU 的 LDS / VGPR / SGPR 上限属 ADR-038 固定容量，于 **2026-11-20 定案**（`kMaxWorkgroups=2^20`、CU LDS=64 KiB/CU、驻留=16 waves/CU、FIFO=8 项、描述符堆=64K 项、`kMaxParamBufBytes=4 KiB`、计算 scratch ≤4 KiB/线程·4 B 对齐·不清零），登记于 `bit-budget.md` §7.1（对应 `B-036~B-041`），新增或改值一律走 §7.4。

**数值容差表**（唯一口径，容差集中管理于 `tools/ref_model/tolerances.toml`）：

| 数据类 | 判据 | 口径 |
|---|---|---|
| 索引、整型、位域、计数、覆盖率 | 逐字节 | 0 容差 |
| fp32 `add / mul / fma / div / sqrt` | ≤ 1 ULP | 前提：参考模型用**同一 op 序与同一 FMA 合并规则**；`tolerances.toml` 可配置 |
| fp32 超越函数（`sin / exp / log / pow`） | ≤ 2 ULP | 实现不同源，须在 `tolerances.toml` 登记 |
| UNORM / sRGB 格式转换 | 逐字节 | 固定舍入规则（与 26 章同实现） |
| 归约 / 原子累加 | ≤ 1 ULP + 顺序断言（强制） | 归约按 lane 升序、原子按 `gtid` 升序累加（§7.1 规则 4） |
| 排序 tie-break | 稳定序断言 | 相等键按输入 `gtid` 定序 |

> **容差权威（2026-11-20 定案，D4）**：容差权威已在 `docs/design/scene-specs.md` §1.2「计算数值口径」定案（fp32 基本运算 ≤1 ULP 且 `tolerances.toml` 可配置、归约顺序断言强制），并登记 `tools/ref_model/tolerances.toml`；本表只作引用。

**专项用例（负向与边界必须真实覆盖）**：

1. 组驻留边界：`block=1024` 且 LDS 接近上限 → 组整体排队但**不死锁**（watchdog 不触发）；
2. 部分波：`block=100` → 4 个波、末波 4 lane 有效，波数断言 = `ceil(100/32)`；
3. 跨 wave barrier：`block=1024`（32 波）barrier 放行正确（S18 case-08 类）；
4. 非一致 barrier：barrier 处于分歧控制流 → 必须 `InvalidIsa` 中止（负向用例）；
5. 间接参数越界：`grid=0` 或超 `kMaxWorkgroups` → 确定性中止且可定位；
6. 双入口等价：同一 WA 在 `hli` 与 `compute` 两入口输出逐字节一致；
7. async 交叉：WA-11 在 compute 与图形队列并行下，硬判据与串行一致。

### 6.8 计算线风险与缓解

| 风险 | 触发点 | 缓解 | 判据 |
|---|---|---|---|
| 组驻留预算算错 → barrier 死锁 | 31 章 occupancy 账本 | 组整体排队规则（§3.12 M-03）+ 专项用例 1 | 不死锁、watchdog 不触发 |
| LDS bank 冲突被误判为正确性问题 | 30 章 LDS 布局 | 冲突只进软观测，结果按 ≤1 ULP 判（同序 FMA 下期望 0 ULP，告警不阻断，scene-specs §1.2） | 冲突计数仅记录 |
| 内存序遗漏（device 作用域未 flush） | 30、31、33 章 | 一致性矩阵逐格用例 + barrier 前后中间值快照 | 矩阵每格可复现 |
| 末波 `LaneMask` 处理错误 | 4、31 章 | 专项用例 2（block=100） | 波数与 lane 有效性断言 |
| 间接参数执行中被重读 | 33 章 | 展开前读一次的契约（D-10） | 参数改动不改变本次结果 |
| 双入口各写一套校验，口径漂移 | 37（直连 HLI）/ stage3 42（计算驱动） | 校验只在 HLI 创建 / 记录期一处，驱动透传 | 两入口拒绝集合一致 |
| 参考模型 op 序不同导致 ULP 争议 | 7、18 章 | 同 op 序 + FMA 合并规则写入 `tolerances.toml` | 容差表评审通过 |
| async 顺序依赖提交次序 | 32、33 章 | 依赖只用 fence / semaphore 表达 | 打乱提交次序结果不变 |
| occupancy 上限配置漂移 | 31 章 | 上限进 ADR-038 配置表；超限排队不报错 | 不同上限硬判据一致 |
| 计算寄存器压力挤压图形并行 | 31 章 | 只做软观测（每线程负载、波分布） | 不进硬判据 |

变更流程（缺一步不允许合并）：

1. 新建 ADR，写明背景、备选方案、最终决策、受影响章节；

**排期硬约束**：① 初级第 3 章完成前不引入任何并发；② 初级第 6 章完成前不谈性能与并行；③ 高级第 23 章完成前不谈性能；④ 高级第 31 章完成前不谈并行收益；⑤ 35.1 冻结前不谈 API 兼容与计算驱动。

**窗口可视化交互工具（拾取 / 调试视图 / 帧 dump）在高级 E 阶段作为可选开发工具落地**，不进入任何自动判据（窗口功能清单见 `docs/design/validation-model.md` §8）。
