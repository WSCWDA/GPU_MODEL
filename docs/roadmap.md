> 定位：章级任务分解与执行路线图。它将 [项目总体设计与任务规划](README.md) 中的正式阶段和工作包展开为章号、任务、依赖与门禁，不另行决定项目总体范围或产品顺序。

### 0.2 阶段与两条纵向线

| 阶段 | 章 | 目标 | 阶段门禁 |
|---|---|---|---|
| 初级（原理最小管线） | 1~9 | 一条 draw 从提交到上屏的完整链路，端到端出图 | E0~E5 全绿，两次运行全图逐字节一致 |
| 高级图形与共用底座 | 10~36 | 地址/内存、执行并行、图形流水线、多队列与 HLI | 按 §2.3 分别验收 A–E。图形适配器按能力选做，S15 验收一期拒绝行为 |

| 计算驱动开发线（stage3） | 38~42 | MUSA 风格计算驱动落地与 demo：context/module/function/stream/event、LaunchKernel、参数打包、stream/event 异步、组内协作/间接派发/UAV 写回、双入口等价验收 | A38~A42 全绿；S18/S19 经计算驱动入口与直连 HLI 入口逐值等价；E/S 场景回归不退化 |

- 计算线的设计（通路、workgroup/wave 映射、内存作用域、MUSA 驱动对象模型）见 `docs/design/compute-line.md`；计算线通路**开发任务以独立第 37 章收口**（ADR-013 修订，2026-11-19）；MUSA 风格计算驱动的对象模型与 ABI 见 `docs/design/compute-driver.md`，**开发任务以 stage3 新章 38~42（`docs/stage3/`，ADR-047）作为计算驱动开发线承载**，双入口等价为主验收。

| ADR-053 | 驱动教学任务与验收边界 | 20 校验预构造参数，37 消费，39 打包并闭合单队列；32 负责队列终态，35.1 验证最小图形 UMD，40 验证双 UMD，41 接入既有能力，42 复用场景进行语义对照 |

### 0.4 异常处理简化（ADR-011）

- **只处理一般错误**：非法 VA、非法包类型/长度、ISA 解码失败、越界绑定等"能定位到单元 + 位置"的问题。
- **最小手段**：接口返回 `Result` + 一条错误日志 + 一条错误记录 `{unit, packetType, dwordOffset, va, code}`；不做重试、不做全链路错误传播、不做自动恢复。
- 应用和驱动参数错误通过返回值交给调用方。硬件执行错误记录后中止当前提交。初级以错误返回收口，第 36 章接入引擎级复位。
- **与第 36 章的关系**：第 36 章只做到"故障可定位 + reset 后可重跑"，不扩展到容错运行；复位为**引擎级**（仅重编程该 ring），不做设备级重启（详见 `docs/design/boot-reset.md`）。

### 0.5 能力四档（ADR-025）

| 档 | 内容 | 处理 |
|---|---|---|
| 初级实现 | 1~9 章 + E0~E5 | 必须实现，不许降级 |
| 高级一期（P0） | 10~37 章及 stage3 38~42。35.1 为必需项，35.2~35.4 为可选适配器 | 按 A–G 验收核心能力，适配器按 capability 矩阵验收 |
| 高级二期 | Task/Mesh Shader、Multiview、Conservative Raster、完整抢占与 TDR | 只留 capability bit，一期返回"不支持" |
| 范围外 | 稀疏资源、RenderPass 对象模型、压缩纹理、可变 subgroup、视频引擎、虚拟化、电源/热、周期级时序、ECC、细粒度页错误恢复、API/二进制兼容 | 永不实现 |

每项能力必须归入上述四档之一，不得留空；高级二期项必须在 HLI 暴露 capability bit，一期调用返回"不支持"而不是静默降级。35.1 的 `Capability` 枚举必须显式包含二期四位（Task/Mesh Shader、Multiview、Conservative Rasterization、设备丢失/TDR/抢占），一期恒 `false`，UMD 与计算驱动只读 HLI 能力位、不得自行映射（Q-72）。各档细目如下。

**初级范围（1~9 章，必须实现，不许降级）**：§2.1 全部 9 章 + E0~E5 场景；一条完整通路（提交 → 取命令 → 地址 → 顶点 → 着色器 → 固定功能管线 → 纹理 → 输出上屏）；仅串行、单上下文、单队列、单 RT。

**高级一期（P0，纳入实现）**：

- 10~34、36 全部硬件章节与 P0 功能补强项：全阶段 UAV、Bindless、视图分离、管线对象、push constant、屏障与所有权转移、独立 DMA 引擎、Early-Z/Hi-Z/fast clear、数组/Cubemap、独立采样器、插值修饰符全集、点线光栅、LoadOp/StoreOp、双源混合、内存序映射、三维 workgroup、GPU 侧谓词、完整 Tess/GS、多视口；
- 第 37 章收口 Compute 派发、参数描述符读取与 uniform 装载，复用 workgroup 映射、组内协作、队列、间接命令、UAV 与查询。`ArgPack` 的主机布局与打包归第 39 章。
- 必须覆盖的功能缺口：实例化渲染（`baseVertex`/`baseInstance`/`InstanceID`，22）、Clip/Cull Distance（24）、PS 输出到 RT 存储格式转换（UNORM/SNORM/UINT/SINT/sRGB，26）、命令包版本号（1、10；高级 `version=2` 并拒绝 v1）、标准化能力查询接口（35.1）、描述符堆设备内存更新语义（20）、动态状态命令缓冲快照语义（35.1）；
- 35.1 HLI 是一期共用底座。35.2 Vulkan、35.3 D3D12、35.4 OpenGL 为按 capability 矩阵交付的可选图形适配器。stage3 38~42 在第 37 章之后交付 MUSA 风格计算驱动。
- S0~S19 高级场景 + 校验工具链 `tools/{ref_model, image_diff, pick_probe, scene_snapshot, spec_runner, log_analyze, mem_audit}` + 完整场景规约单份 `docs/design/scene-specs.md`；窗口可视化工具高级 E 阶段可选（§9 里程碑）。

**高级二期（只留 capability bit，一期不实现逻辑）**：

| 能力 | 一期行为 | 二期内容 |
|---|---|---|
| Task / Mesh Shader | 能力位 false，创建即报"不支持" | 按 S15 二期判据验收；光栅输入来自 Mesh 输出图元，不再依赖传统 IA |
| Multiview | 同上 | 多视图实例化 |
| Conservative Rasterization | 同上 | 保守光栅 |
| 设备丢失 / TDR / GPU 抢占 | 只做 36 章定位与复位 | 完整抢占与恢复 |

**项目范围外（永不实现）**：稀疏资源 / 虚拟纹理（页错误路径只服务驻留，不构成 sparse 绑定模型）；Vulkan RenderPass / subpass 对象模型（只建模 LoadOp/StoreOp）；BC 等压缩纹理格式（只做未压缩基础格式）；可变 subgroup size、自定义 lane swizzle（固定 warp32，lane 顺序即线性顺序）；视频编解码硬件引擎；SR-IOV / MIG / GPU 虚拟化 / 多进程共享；电源、频率、热管理；周期精确时序、总线时序、DRAM 时序、带宽与绝对性能建模；真实指令周期与流水线级延迟（只做功能级停顿）；硬件级 ECC、可靠性、容错重试；具体游戏引擎或资产管线；细粒度页错误恢复（wave 暂停/恢复：复位由 36 章引擎级接入，不做设备级重启）；MUSA / CUDA 的 API 或二进制兼容（只借鉴对象模型与调用路径）；Mesa 代码级复用或内部接口兼容（只借鉴分层、对象生命周期与 IR 形状）；屏障逐访问位掩码（一期只做 READ / WRITE / ATTACHMENT / TRANSFER 粗粒度集合，不做 per-resource 位图，登记为简化）。

### 0.6 计算线兼容原则

计算线整体在高级阶段引入，但兼容性在图形线推进中就必须付清：

1. 分层不为图形特化：`IShaderArray`、内存、缓存、队列、fence、描述符、查询均为 workload 无关。
2. 第 1 章冻结 `Stage::Compute`、`ThreadIdSpace`、`DispatchArgs`，即使暂时无人消费。
3. 第 20 章描述符同一套支持 SRV/UAV/CBV/Sampler，并为 kernel 参数缓冲预留绑定方式。
4. 第 32、33 章队列与 IB 不区分 draw/dispatch，间接与 predication 对两者同构。
5. 第 4、15、29、30、31 章的 SIMT、分歧、subgroup、shared/atomic 不得假设"只有一个 PS 阶段"。
6. 共用单元只能按包类型派发，不得出现"图形专用/计算专用"分支。

> 计算线的完整模块设计见 `docs/design/compute-line.md`；开发任务以独立第 37 章收口（ADR-013 修订），图形线预留点见 §6.1、启动条件与验收见 §6.3。

### 0.7 硬件行为原则（FPGA 视角）

模拟定位是"类似于 FPGA 的工作"：除功能正确外，以下行为特征作为全项目统一的实现原则，各落实为 ADR 并在对应章内以子里程碑落地。它们回答的是"GPU 为什么这么设计"（深流水线、延迟隐藏、标量/向量分工、occupancy），不是单纯的功能堆叠。

| 原则 | 内容 | 落点 |
|---|---|---|
| 功能级流水线与背压 | 单元间以输入 FIFO + 输出 FIFO + valid/ready 握手连接；下游忙（FIFO 满）则反压上游停发；多图元 / 多波可同时在不同阶段流动（不做周期精确） | ADR-035；第 4、10、23、25 章 |
| 延迟隐藏 | 高延迟操作（纹理采样等）异步化：波挂起 → 让出执行资源给就绪波 → 结果返回唤醒；这是理解 SIMT 调度动机的前提 | ADR-036；第 15、21 章 |
| 标量 / 向量分区 | ISA 层面区分标量指令与向量指令，SGPR / VGPR 独立编号空间，波内一致值走标量通路；现在定死编码，后期加计算不返工 | ADR-034；第 5、16、17 章 |
| MMIO 唯一硬件接口 | 一切配置、状态、统计只经 MMIO 寄存器读写，单元内部成员私有；接口与实现解耦，调试工具只依赖 MMIO | ADR-037；第 2、10 章 |
| 硬件资源上限 | 资源容量物理固定（驻留 wave / SGPR / VGPR / LDS / FIFO / 描述符堆），超限排队等释放，模拟真实 occupancy 限制 | ADR-038；第 31 章 |
| 状态机实现单元 | 单元核心逻辑用有限状态机（FSM）而非过程式代码，如 CP：空闲 → 取包头 → 解析 → 派发 → 写 fence → 空闲 | 第 2、10、21 章起 |

> 各原则机制细节的模块设计见 `docs/design/{execution-parallel, memory-system, isa-abi, command-mmio}.md`。

### 2.4 任务拆分模板（四段式）

每个实施任务明确一个主要原理、直接输入、输出与可观察的通过条件。开工时确认本次触达的公共契约。先用最小输入或支架验证局部行为，再在依赖齐备后接入正式场景。

|---|---|
| 契约 | 输入、输出、所有者和错误语义可追溯。复用已定义类型和编号 |
| 局部行为 | 最小正常输入能解释结果，边界输入能解释拒绝或停顿 |
| 接入 | 生产者和消费者使用同一共享接口，有从输入到输出的证据 |
| 验收 | 章内保留 A<n> 和 R_n，阶段按 §2.3 汇总 |

四段用于组织证据。小任务可一起交付契约、实现与验证。若一个子里程碑同时改变两个独立规则，或必须同时调通多个子系统才能验证，先拆到独立产物，再安排接入。

### 2.9 测试场景规约（单份场景文档）

E0~E5 / S0~S19 的完整规约集中在**单份 `docs/design/scene-specs.md`**（不建 `docs/scene-specs/` 目录），文件内每场景一节（`Exx_` / `Sxx_` 小节）。模块设计见 `docs/design/validation-model.md`，本节只落任务与验收相关约束：

- **场景文档是冻结契约**：修改场景输入、探针集、阻断判据、KFT 绑定，必须走 §7.4 契约变更工作流（新建 ADR）；`apps/scene_*` 严格对齐该文件对应节，不得私自修改输入参数。
- **判定四分类** 阻断门禁（CI 失败）/ 仅告警 / 纯观测统计 / 仅人工检视；每项含容差与失败行为，写入对应场景的判定矩阵。
- **初级 E 输入永久冻结**：只能改探针容差，几何/纹理/背景值不得改动；高级 S 的探针表 L2 为阻断门禁，全图差分仅告警。
- **子 case 与 KFT**：同一个二进制跑多组输入（case-0 … case-N），复用同一套探针与判据；二期未实现能力绑定为 KFT 子 case，CI 命中只告警、不计入失败。
- **入库规则**：spec 文档、探针文本表、初级 E 的 `.raw` 基线入库；PNG、差分图、trace 日志为 CI 临时产物、不入库。
- **参照源只有 CPU 参考模型**（`tools/ref_model` / `docs/design/validation-model.md`），不做真机/外部 GPU 参照渲染；验收不依赖任何外部图形 API 或渲染后端（ADR-027）。
- **高级 S 双轨校验**：L1/L2 探针保持阻断门禁；另加**非阻断全图掩码差分（仅告警）**，阈值 `max_allowed_bad_pixels`，捕捉无探针区的大片缺陷；严禁升级为阻断门禁（并行/浮点噪声会造成 CI 抖动）。
- **基线存储**：高级 S 不存任何图像基线，期望值运行时由 `ref_model` 生成，仓库只存探针文本表；PNG 不入库；初级 E `.raw` 基线入库（`docs/design/scene-specs.md` §1.4）。
- **CI 诊断与矩阵**：失败提供场景配置、实际与期望结果、差分和必要 trace。按场景表中的适用组合执行 Windows/Linux 工具链、执行策略、缓存和入口。初级全字节校验禁用 `-ffast-math`。
- **KFT 绑定 issue**：场景或探针点可标记 KFT 并绑定 issue 编号，`kft_allow=on` 输出警告不阻断门禁；禁止直接注释/删除测试，功能实现后移除标记。
- **窗口与 headless 解耦**：窗口是高级 E 阶段可选调试工具（放 `umd/os`，只做 CPU 帧 → 宿主 GPU blit），不参与渲染计算；`frame_index` 由提交驱动、禁 vsync/墙钟；校验不依赖窗口，headless 可完整跑全部 E/S（`docs/design/validation-model.md` §8，构建开关 `BUILD_WITH_WINDOW`）。

## 3. 执行顺序与依赖

### 3.1 按依赖推进（ADR-014）

1. 任务按 §2.1 的分组和章内子里程碑推进。编号用于追溯。局部验证和真实场景接入分别声明直接前置。
2. 章级按 §2.1 的直接前置与 §3.2 例外安排。A<n> 收口本章，回归按 §7.4 的 `R_n` 执行。
3. **阶段级**：§2.3 三列门禁全绿后才进入下一阶段。
4. 依赖之间可交换的工作按 §3.2 排列。涉及同一冻结契约的修改先完成裁决与登记。
5. **契约先行**：任何跨章契约变更，先改 ADR 与架构文档，再改代码。

### 3.2 允许交换的顺序对

以下交换不改章号、不改任务编号，只调整推进先后：

| 可交换 | 条件 | 理由 |
|---|---|---|
| 19 ↔ 20 | 第 18 章完成且第 20 章的直接契约齐备 | 可开展第 20 章接口和主体工作，C 阶段正式收口仍须满足 B 阶段门禁 |
| 34 提前到 31 之后 | 阶段 D 通过 | 可先实现查询与统计主体，GPU 谓词接入依赖第 33 章的命令支持 |

> **12 与 14 不可交换**：第 14 章逐出前必须调用第 12 章 `CacheSubsystem` 完成 flush，依赖单向（Q-47）。

### 3.3 章号顺序的例外说明

- **4/15 与 5/16**：初级第 4、5 章用"内存内指令结构 + 语义"实现执行与最小 ISA；高级第 15、16 章才补齐分歧、控制流栈与完整二进制编码。初级验收看"语义与寄存器终态"，高级验收看"往返二进制一致"。
- **17、18、19**：第 18 章必须先把手写后端定稿（含寄存器分配与发射），第 19 章按 ABI/ISA 合法性与规范程序语义对照验收；不要求 blob 逐字节一致，也不阻塞 20，否则后端缺陷会被数据通路掩盖。
- **20 与 16**：资源与绑定依赖 ISA/ABI 冻结，但可以先于几何前端实现；第 21 章纹理接在其后。
- 20~34 章使用共用命令和资源契约做分章验收，可使用最小提交门面或测试支架。35.1 固定对象面后分批接入实际 HLI。第 37 章使用同一 HLI 完成计算通路。
- **36 贯穿全程**：10~35 各章在实现时保留错误码与"单元 + 包类型 + dword 偏移"定位钩子；第 36 章最后统一收口 watchdog、复位与故障注入，不把错误处理推迟到 36 才从零补。

### 3.5 初级爬升纪律

## 5. 双执行策略与并行度

> 模块设计与"时间无关 + 确定性"的完整职责见 `docs/design/execution-parallel.md`；配置键为**唯一权威定义**，`architecture-design.md`、`docs/design/*` 引用时不得另立取值。

### 5.1 配置（权威全表）

| 键 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `exec_mode` | `serial` / `parallel` | `serial` | 策略 A / B |
| `worker_threads` | `1..N` | 1 | 工作线程数；超过硬件单元数的部分忽略 |
| `se_count` | `auto` / `1` / `2` / `4` / `8` | `auto` | `auto = min(hardware_concurrency, 4)`；CI 固定 1 |
| `tile_w` | 正整数，≤ `rt_size` 宽 | 4 | SE 屏幕分块宽；仅 `parallel` 生效，与第 25 章固定 2×2 quad 解耦；边缘按部分 tile 处理（D31.2 tile 并集=全屏、互不重叠） |
| `tile_h` | 正整数，≤ `rt_size` 高 | 4 | SE 屏幕分块高；仅 `parallel` 生效，与 2×2 quad 解耦；同上 |
| `warp_size` | 固定 32 | 32 | 不开放，避免基线漂移 |
| `cache_enable` | `on` / `off` | `on` | `off` 旁路显式 GPU 缓存，已定义的内存可见性与场景结果一致。缓存统计用于观察 |
| `rt_size` | `256x256` / `1280x720` / 自定义 | `256x256` | 场景底板尺寸 |
| `api_backend` | `hli` / `graphics` / `vulkan` / `d3d12` / `gl` / `compute` | `hli` | `graphics` 为最小图形 UMD，外部适配器取声明子集，`compute` 用于 stage3 已接入的用例 |
| `trace` | `off` / `<unit>` | `off` | 单步打印指定单元输入输出，仅供人工 |
| `dump_raw_output` | `off` / `on` | `off` | 校验失败时自动导出原始 raw 帧，CI 诊断制品 |
| `max_allowed_bad_pixels` | `0..8192` | `256` | 全图掩码差分告警阈值，仅告警不阻断 |
| `kft_allow` | `off` / `on` | `off` | 开启 KFT（Known-Failing-Test）警告输出 |
| `log_level` | `Error`/`Warn`/`Info`/`Debug`/`Trace` | `Warn` | 日志等级；CI 只 `Error`/`Warn`，Debug/Trace 编译期可裁剪 |
| `hw_counters_enable` | `on`/`off` | `off` | MMIO 只读硬件统计计数器；仅软观测不阻断 |
| `mem_sanitizer` | `on`/`off` | `off` | GPU 内存 Sanitizer（越界/UAF/未初始化读）；默认关，调试用 |
| `translation.seed` | u64 | — | 页表 / TLB / 堆分配的确定性伪随机种子；同种子下 GPU VA 序列与 TLB 替换序完全一致（11 章） |
| `memory_budget` | 字节数 / `auto` | `auto` | GPU 地址空间预算上限；`auto` 按堆类型取默认值，超限返回 `OutOfMemory`（11、14 章） |
| `simd_per_cu` | `1` / `2` / `4` | 1 | 每 CU 的 SIMD 数量；只影响波调度分布与软观测，不改变硬判据（15、31 章） |

- `tile_w` / `tile_h` 只决定第 31 章 SE 屏幕分块粒度与负载统计，不改变像素 / 探针结果；任何取值都必须保持像素结果不变（屏幕边缘按部分 tile 处理：`tilesX = ceil(rt_width/tile_w)`、`tilesY = ceil(rt_height/tile_h)`）。

### 5.2 两种策略

| | 策略 A：确定性串行 | 策略 B：硬件对齐并行 |
|---|---|---|
| 线程 | 单线程 | N 个工作线程（与 `se_count` 独立配置） |
| 波领取 | 固定顺序 | CU 内原子领取 |
| 图元/像素顺序 | 固定 | SE 屏幕 tile 静态分区，区内确定 |
| 内存 | 单一 TLB 视图 | 线程本地 TLB + 全局失效 |
| 用途 | 黄金基线、问题定位 | 观察并行行为、性能差异、竞争缺陷 |

### 5.3 各章与策略的关系

| 章 | 与双策略的关系 |
|---|---|
| 1 | 冻结配置键与"硬判据/软观测"定义，不实现策略 B |
| 2、10 | 环与 CP 在策略 B 下仍是单点消费，包序不被多线程打乱 |
| 3、11 | 地址翻译必须线程安全或明确"仅单线程"，为 31 章留扩展点 |
| 4、15 | 波执行与分歧轨迹在策略 A 下确定；策略 B 下同波结果不变 |
| 12 | `cache_enable` 开关前后逐字节一致；S11 只跑 `se_count=1` 的退化子集 |
| 13 | Display 只在提交完成后读 RT，不与执行并发 |
| 14 | 两上下文互不污染在两种策略下都必须成立 |
| 22、23 | 切片粒度与 `worker_threads` 解耦：切片数由容量决定，线程数只决定谁执行 |
| 29、30 | 归约/原子必须定义归约顺序；barrier 不得依赖线程到达顺序 |
| 31 | 实现策略 B：线程池、SE tile 静态分区、CU 原子领取、线程本地 TLB + 全局失效 |
| 32、33 | 多队列依赖顺序由 fence/semaphore 定义，不得依赖线程调度 |
| 34 | 查询归约顺序固定；timestamp 只做单调性判定 |
| 35 | 直连 HLI 核心场景通过。已实现图形适配器按 capability 子集做差分并保留 HLI 命令语义 |
| 36 | 故障注入在两种策略下都能定位到单元与位置 |
| 37 | 直连 HLI 的 S18/S19 通过两种执行策略判据。双入口等价由第 42 章验收 |
| 38~42 | 38~41 按章验证已接入子集，第 42 章验收 S18/S19 双入口逐值等价及适用的串行/并行组合 |

### 5.4 判据与回归矩阵

计算线场景的前置章节使用局部向量，第 37 章验收直连 HLI，第 39 章启用驱动的 S18 `case-3`，第 42 章按场景规约汇总双入口矩阵。入口选择沿用 `api_backend`。

- 硬判据以场景登记为准。颜色、深度、覆盖按各自容差校验，结构计数、栅栏顺序及明确的横向差分按对应断言比较。timestamp 验证逻辑值单调。
- **软观测（允许不同，只记录）**：墙钟耗时与加速比、缓存 / TLB / I-Cache 命中率、每 SE 波分布、每线程负载、每级 FIFO 平均占用率与反压周期计数、波切换次数、非探针像素。
- **双策略**：`serial` 与 `parallel` 在探针点上必须**零容差**一致；参照源为 CPU 参考模型，容差集中管理于 `tools/ref_model/tolerances.toml`。
- **全图逐字节**：初级作为主判据；高级只保留 `--dump-all` 调试导出。
- **31 章之前**：`exec_mode=parallel` 必须显式报"策略 B 未实现"，**不得静默退化为串行**。
- **31 章之后**：S11 必须覆盖 `se_count ∈ {1,2,4,8} × worker_threads ∈ {1,2,4}` 的可用组合；任一硬判据不一致，先按正确性缺陷处理。
- `spec_runner` 对登记的适用组合独立判定，失败产生场景规约 §1.5 的诊断产物。阻断项按原配置上报，KFT、告警、观测与人工检视按场景规定处理。

### 5.5 确定性规则

1. **无时间输入**：着色器 uniform 与 CPU 位姿计算禁止 `uTime`、`clock()`、墙钟差值。
2. **位姿可复算**：只由 `(scene_id, frame_index, camera_params, model_matrix)` 决定；`frame_index = n` 与"直接以 n 初始化"必须一致。
3. **遍历顺序固定**：图元、像素、描述符、资源的遍历顺序显式定义；并行时按 tile/wave 分区并固定区内顺序。
4. 场景要求确定的浮点归约使用场景规约规定的顺序与树形组合。无数据竞争的工作组允许并行，原子负载按已定义语义与场景断言验证。
5. **无未定序随机**：扰动使用固定种子且消费顺序固定，禁止每线程各自取随机数。
6. **平局可判**：深度相等、时间戳相等、稳定排序必须给出确定 tie-break（如按 primitive id）。
7. **内存序显式**：原子与屏障使用 `Relaxed / Acquire / Release / AcqRel / SequentiallyConsistent`，作用域区分 `Workgroup / Device`；shared 栅栏与全局资源屏障是两套机制。

### 6.7 计算线验收矩阵与判据口径

下表给出计算验收的配置维度。每个 case 实际启用的入口、策略、命令和队列方式以场景规约为准，已登记的阻断组合须逐项判定。

| 维度 | 取值 | 要求 |
|---|---|---|
| 入口 | `hli`（37 主验收） / `compute`（stage3 42 双入口等价） | 逐值等价（不只是"都能跑通"） |
| 执行策略 | `serial` / `parallel` | 探针与数值零容差一致 |
| 业务类 | WA-01~WA-12 | 按下方容差表判定 |
| 缓存开关 | `cache_enable=on/off` | 逐字节一致 |
| dispatch 形式 | 直接 / 间接 | 逐值等价 |
| 队列形态 | 单队列 / compute 队列 + 图形队列并行 | 比较定义的结果。跨队列顺序由 fence/timeline 确立，资源可见性和所有权按屏障契约判定 |

**配置口径**：计算线**不新增配置键**（§5.4）；`DispatchDesc` 的取值由场景子 case 携带，不进 §5.1 配置表；`kMaxWorkgroups` 与 CU 的 LDS / VGPR / SGPR 上限属 ADR-038 固定容量，于 **2026-11-20 定案**（`kMaxWorkgroups=2^20`、CU LDS=64 KiB/CU、驻留=16 waves/CU、FIFO=8 项、描述符堆=64K 项、`kMaxParamBufBytes=4 KiB`、计算 scratch ≤4 KiB/线程·4 B 对齐·不清零），登记于 `bit-budget.md` §7.1（对应 `B-036~B-041`），新增或改值一律走 §7.4。

**数值容差表**（唯一口径，容差集中管理于 `tools/ref_model/tolerances.toml`）：

| 数据类 | 判据 | 口径 |
|---|---|---|
| 索引、整型、位域、计数、覆盖率 | 逐字节 | 0 容差 |
| fp32 `add / mul / fma / div / sqrt` | ≤ 1 ULP | 前提：参考模型用**同一 op 序与同一 FMA 合并规则**；`tolerances.toml` 可配置 |
| fp32 超越函数（`sin / exp / log / pow`） | ≤ 2 ULP | 实现不同源，须在 `tolerances.toml` 登记 |
| UNORM / sRGB 格式转换 | 逐字节 | 固定舍入规则（与 26 章同实现） |
| 归约 / 原子累加 | ≤ 1 ULP + 顺序断言 | 遵循 [场景规约 §1.2](design/scene-specs.md) 的固定 `gtid` 顺序与组内树形组合 |
| 排序 tie-break | 稳定序断言 | 相等键按输入 `gtid` 定序 |

> **容差权威（2026-11-20 定案，D4）**：容差权威已在 `docs/design/scene-specs.md` §1.2「计算数值口径」定案（fp32 基本运算 ≤1 ULP 且 `tolerances.toml` 可配置、归约顺序断言强制），并登记 `tools/ref_model/tolerances.toml`；本表只作引用。

**专项用例（负向与边界必须真实覆盖）**：

1. 组驻留边界。`block=512` 且 LDS 接近上限，可调度的组在资源被占时整组等待，资源释放后完整推进。
2. 部分波：`block=100` → 4 个波、末波 4 lane 有效，波数断言 = `ceil(100/32)`；
3. 跨 wave barrier：S19 case-0 的跨波参与条件按场景规约验证。512 线程的边界用例用于覆盖 16 波整体驻留。
4. 非一致 barrier：barrier 处于分歧控制流 → 必须 `InvalidIsa` 中止（负向用例）；
5. 间接参数越界：`grid=0` 或超 `kMaxWorkgroups` → 确定性中止且可定位；
6. 双入口等价：同输入按 A42 比较关键命令语义及探针，覆盖范围以场景规约为准。
7. async 交叉：WA-11 在 compute 与图形队列并行下，硬判据与串行一致。

### 6.8 计算线风险与缓解

| 风险 | 触发点 | 缓解 | 判据 |
|---|---|---|---|
| 组驻留预算算错 → barrier 死锁 | 31 章 occupancy 账本 | 组整体排队规则（[架构设计 §3.12](architecture-design.md) M-03）+ 专项用例 1 | 不死锁、watchdog 不触发 |
| LDS bank 冲突被误判为正确性问题 | 30 章 LDS 布局 | 冲突只进软观测，fp32 结果 ≤1 ULP 通过、>1 ULP 阻断；同序 FMA 下 0 ULP 仅为诊断信息（scene-specs §1.2） | 冲突计数仅记录 |
| 内存序遗漏（device 作用域未 flush） | 30、31、33 章 | 一致性矩阵逐格用例 + barrier 前后中间值快照 | 矩阵每格可复现 |
| 末波 `LaneMask` 处理错误 | 4、31 章 | 专项用例 2（block=100） | 波数与 lane 有效性断言 |
| 间接参数执行中被重读 | 33 章 | 展开前读一次的契约（D-10） | 参数改动不改变本次结果 |
| 双入口各写一套校验，口径漂移 | 37（直连 HLI）/ stage3 42（计算驱动） | 校验只在 HLI 创建 / 记录期一处，驱动透传 | 两入口拒绝集合一致 |
| 参考模型 op 序不同导致 ULP 争议 | 7、18 章 | 同 op 序 + FMA 合并规则写入 `tolerances.toml` | 容差表评审通过 |
| async 顺序依赖提交次序 | 32、33 章 | 用 fence/timeline 与必要的资源屏障表达依赖 | 变换合法提交次序后，等待与可见性仍符合定义 |
| occupancy 上限口径漂移 | 31、37 章 | 按 ADR-038 固定容量。组需求超限时拒绝，只有暂时占用时排队 | 分别覆盖拒绝和等待后完成 |
| 计算寄存器压力挤压图形并行 | 31 章 | 只做软观测（每线程负载、波分布） | 不进硬判据 |

### 7.4 契约变更工作流

冻结契约范围：

1. 初级契约（`stage1/01-contracts-min.md`）；
2. 高级 HLI 命令包格式与 HLI 对象接口（35.1）；
3. 场景输入：E0~E5 的几何/纹理/配置（永久冻结）、S0~S19 的探针集与阻断判据；
4. 场景规约：`docs/design/scene-specs.md`（单份）的输入、探针集合、阻断判据、KFT 绑定；
5. **编号空间**（包类型 / `stateId` / MMIO 段 / opcode 区段 / 页表位宽）：引入内存间接状态表、包内 `SubOp` 子操作码、`INDIRECT` 间接缓冲、页表级数变更、opcode 重编号等，均属契约变更（ADR-043/045），必须先对照 `bit-budget.md` 审计。

变更流程（缺一步不允许合并）：

1. 新建 ADR，写明背景、备选方案、最终决策、受影响章节；
2. 更新契约文档（`architecture-design.md` §3 / `docs/design/` 对应模块）；
3. **登记编号空间**（§7.3）后更新所有受影响场景的 DoD 与判据；
4. 按 `R_n` 回归直接受影响且仍有效的已交付 E/S 判据。替换的旧 DoD 标为 `SUPERSEDED` 并注明接替项。阶段汇总按 §2.3 的正式矩阵执行。
5. 评审通过后合并。

禁止项：改契约不改判据；35.1 冻结后 UMD 阶段反向修改 HLI；为通过测试而修改探针期望值；未审计 `bit-budget.md` 直接硬编码新增编号。

| 5 | 双策略（按 §5.3 的阶段与适用性） | 探针点零容差一致 |

> 场景规约维护输入、阈值和失败等级。其章表列出场景关联。若某场景还需要后续能力，章验收按 §2.1 与章文档 §7 标注的已交付子集执行。第 20、29–31、33 章借用的计算输入只作单元验证，完整 S18/S19 由第 37 章首验，第 42 章做双入口对照。

### DoD 修订与 SUPERSEDED 流程

每章回归范围记为 `R_n`，在对应 stage 文档 §7 的「回归项」列出；仅纳入本章变更直接影响、仍有效且未被标记为 `SUPERSEDED` 的前序场景/判据。`A1~A(n-1)` 不得作为无差别全量门禁；历史 A 仅作验收记录，契约变更通过 ADR 更新受影响集和旧判据状态。

后续章节可以修订前序契约或判据，但必须依次完成：①记录 ADR 与变更理由；②更新 design 唯一登记表及受影响章节；③登记 `旧判据 → SUPERSEDED → 新判据`，保留旧判据供审计但不再作为阻断门禁；④更新契约快照及本章范围内的回归。未完成以上步骤的新增契约不得进入实现。每章只对该章登记的偏移、编号、能力与场景断言；不得将尚未分配的保留空间当作全局不支持行为做硬判据。

### 依赖与任务粒度

各章分别说明局部验证与场景接入的直接依赖。硬件消费、驱动包装、API 适配和端到端验收分别归属。替换重复判据时沿用 `SUPERSEDED` 记录。共享契约和实现简化的写法见 [公共组件设计](design/shared-foundation.md)。
