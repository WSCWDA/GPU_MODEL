# GPU_MODEL 教学任务路线图（U0–U8）

> 本路线图展开 [README](README.md) 的九个教学单元。U 编号是当前任务编号；旧版 1–42 章、WP、EDU、A–G 阶段与 E/S 全量门禁不再决定开工顺序。旧文档保留为技术资料，原任务体系见 [重组前提交](https://github.com/WSCWDA/GPU_MODEL/commit/0b36b1d6dcdc25e1bcc958c5be642653943d0c7c)。

## 1. 如何执行一项教学任务

每个任务留下一份可运行的最小输入、一种可观察的输出、一条解释该输出的关键路径，以及一个能引发可预测变化的实验参数。完成任务意味着学习者能用运行记录解释结果；不要求先完成所有同类硬件细节。

| 标记 | 意义 | 完成方式 |
|---|---|---|
| 核心 | 支撑 C1–C6 综合检查点 | 进入共享模块，提供可运行结果和失败路径 |
| 独立实验 | 讲清一个原理但不接入综合路径 | 使用局部替身或小型独立模型；记录输入、输出及简化 |
| 扩展 | 高级概念的深入练习 | 可以在核心路径完成后独立选做，不阻挡其他单元 |

任务在学习开始时先固定本次实验的输入和观测方式。数据布局、数值常量与算法变体可由实验自行确定；只有接入共用命令、资源、执行和完成接口时才需要同步该边界。对局部文档的小差异，以本实验的明确假设为准，并记录差异，不启动全仓库逐章改写。

## 2. 路线和依赖

| 单元 | 核心交付 | 可独立开展的部分 | 进入综合路径前需要 |
|---|---|---|---|
| U0 可运行与可观察 | runner、结果导出、分级日志 | 场景格式和展示界面 | 无 |
| U1 命令与第一帧 | clear/draw、CP/fence、三角形图 | ring 回绕与中断细节 | U0 |
| U2 可编程着色 | wave、最小 ISA、VS 替换 | 汇编器、前端、LLVM 对照 | U1 的顶点入口 |
| U3 内存与资源 | buffer/view、地址访问和可见性 | 页表/TLB、L1/L2 具体策略 | U0；给 U5/U6 提供资源接口 |
| U4 图形扩展 | 纹理、深度/混合 | MSAA、Tess/GS、查询 | U1；综合帧只取基础部分 |
| U5 计算与协作 | dispatch、LDS/barrier、CPU worker | 更复杂的原子作用域/调度策略 | U2、U3 |
| U6 共用驱动底座 | HLI/KMD/FW 共用提交与内存 | 多队列、抢占、复位 | U1、U3；计算接入取 U5 |
| U7 图形与计算 UMD | 两个入口访问同一设备 | Vulkan/D3D12/GL 风格适配器 | U5、U6 |
| U8 综合演示 | 计算写入 → 同步 → 图形读取 | GUI 和更多场景 | U4 基础、U7 |

U2、U3 和 U4 在 U1 后不必按编号串行。U4 的高级几何实验不参与 U8 的前置检查；U6 可以先接 U1 的图形命令，再接 U5 的计算命令。单元的编号表达教学路径，依赖只在表中所列的具体能力上成立。

## 3. 单元任务

### U0 可运行与可观察

**问题**：没有真实 GPU 时，如何证明一次实验的输入和结果可以复现？

| 任务 | 练习与改动 | 交付和通过条件 |
|---|---|---|
| U0.1 | 建立最小构建、命令行场景入口和内存中的像素/数据缓冲 | 一条命令运行清屏或填充场景，输出原始结果；同一输入能再次得到相同结果 |
| U0.2 | 增加 Error/Warn/Info/Debug/Trace 分级日志与必要的场景、模块、逻辑序号 | 正常运行给出简要摘要；打开 Debug/Trace 能追踪一项数据；关闭细粒度日志不改变结果 |
| U0.3 | 为实验保存参数快照、独立的参考期望和可读差异 | 改一个参数后，输出和解释同步变化；非法输入给出定位信息 |

这时不建立完整驱动对象或模拟全部 GPU 单元。日志文本为人工学习材料，参考结果取自独立计算或可手算的样例。

### U1 命令与第一帧

**问题**：一条应用命令如何抵达像素缓冲，何时算执行完成？

| 任务 | 练习与改动 | 交付和通过条件 |
|---|---|---|
| U1.1 | 定义最少的 Clear、Draw、Fence 命令和可观察的提交/消费过程；使用简易 ring/CP | trace 能指出生产者、CP 和完成位置；fence 完成后才可读出本次写入 |
| U1.2 | 用属性传递型内置 VS 处理三角形，连接简化 IA、裁剪/视口、光栅和 OM | 导出一幅清屏加三角形的图；能追踪一个顶点和一个像素的来源 |
| U1.3 | 提供 headless 原始帧/PNG 导出和一个可手算的像素参考 | 改变顶点或颜色后，预期的像素随之变化；输出与局部参考一致 |

第一帧保留固定功能阶段的概念边界；此时内置 VS 是清楚标注的教学替身，U2 将替换它。不要求 Tess/GS、复杂 PSO、多队列或完整 UMD。

### U2 可编程着色

**问题**：同一条图形路径中的可编程阶段由谁执行？

| 任务 | 练习与改动 | 交付和通过条件 |
|---|---|---|
| U2.1 | 定义一个 wave 的 lane、活动掩码、寄存器与少量算术/访存指令 | 单步记录能解释活跃 lane 的结果和未激活 lane 为什么没有写入 |
| U2.2 | 用小型解释器运行 VS，替换 U1 的内置顶点处理 | U1 同一三角形的关键像素符合参考值；可单独改变 shader 观察形状/颜色 |
| U2.3 | 用一个分支样例说明 lane mask 与重收敛；以内置单 wave vector_add 说明相同执行器可供计算使用 | 每个 lane 的输出可手算；分歧结束后活动范围符合实验定义 |

独立扩展：手写汇编器、简单着色语言前端、SSA/CFG、LLVM 对照。比较规范程序的可观察语义，不要求不同后端生成逐字节相同的机器码。

### U3 内存与资源

**问题**：资源句柄、GPU 地址、缓存和局部暂存如何影响数据到达消费者？

| 任务 | 练习与改动 | 交付和通过条件 |
|---|---|---|
| U3.1 | 给 Buffer/View 建立最小生命周期与读写接口，区分宿主指针和模型地址 | 上传、读取、释放后访问等练习有可解释的结果或错误 |
| U3.2 | 用独立实验从 flat memory 过渡到 VA→PA/TLB；给出同 VA 不同映射或权限案例 | 可以逐步指出地址查找路径；切换实现不改变已定义的 Buffer 读写结果 |
| U3.3 | 在软件中模拟一个小型缓存/写缓冲或阶段局部暂存，观察复用、flush 与可见性 | 说明一次读的数据来源与一次写何时可见；关闭模拟缓存后结果仍符合该实验的语义 |

L1/L2 命中率只辅助解释数据流。patch/control-point、顶点缓冲与 GS 输出可以作为不同的阶段暂存实验；宿主 CPU 的缓存局部性只用于优化模拟器本身。

### U4 图形管线扩展

**问题**：除了顶点变换，图形输出还受到哪些固定功能和几何阶段影响？

| 任务 | 练习与改动 | 交付和通过条件 |
|---|---|---|
| U4.1 | 给 U1 的路径增加最简单的纹理视图，在像素阶段/PS 使用 nearest 采样 | 输出纹理四边形；改变采样坐标能解释像素变化 |
| U4.2 | 增加一个深度比较与一种混合方式 | 两个重叠图元的遮挡与颜色有可手算参考 |
| U4.3 | 独立扩展：用 patch→Tessellation→图元或输入图元→GS→输出图元解释几何放大与局部数据复用 | 一个独立场景显示生成前后图元/顶点数和图像；不要求与 U4.1/U4.2 同时开启 |

MSAA、Hi-Z、复杂格式和更多固定功能变体作为后续实验。U8 只要求 U4.1/U4.2 中选定的基础图形数据流。

### U5 计算与协作

**问题**：计算工作怎样分组，CPU 多核又怎样承载模拟的 GPU 并行？

| 任务 | 练习与改动 | 交付和通过条件 |
|---|---|---|
| U5.1 | 增加 Dispatch(grid, block) 和最小 CS 入口，沿用 U2 执行器、U3 资源读写 | vector_add 中每个输出元素可追溯到对应 work-item；越界 work-item 不写入 |
| U5.2 | 实现一个 workgroup 的共享暂存、barrier 和一种原子归约 | 小输入可手算；跨 wave 参与者到齐后才继续，提前退出能被诊断 |
| U5.3 | 以 workgroup 或独立 tile 为 CPU worker 任务；保留单线程参考执行 | 对无竞争和已定义原子实验，1/多 worker 的结果符合同一参考；记录的 GPU 逻辑 ID 不依赖 OS 线程 ID |
| U5.4 | 独立扩展：用 ballot、shuffle 或 wave 归约讲解 subgroup | 少量 lane 输入可手算；该实验不成为 U6/U7 前置条件 |

禁止以宿主线程完成顺序决定计算结果。未定义数据竞争不列入确定性结果比较；barrier 由模型协作调度，不要求一个 CPU 线程对应一个 lane。

### U6 共用驱动底座

**问题**：图形和计算怎样共用提交、地址和完成机制？

| 任务 | 练习与改动 | 交付和通过条件 |
|---|---|---|
| U6.1 | 建立 HLI 最小 Device/Queue/Resource/Command 对象，先把 U1 的 Draw 翻译到共用提交入口 | 图形提交结果正确，HLI 对象与提交身份可追踪；此任务可在 U5 前开展 |
| U6.2 | 增加模拟的 KMD 上下文/映射/提交及 FW 取环/调度，连接既有 CP | 记录能跟踪一次提交的对象、命令和资源身份；非法地址或命令有确定错误 |
| U6.3 | 接入 U5 的 Dispatch，并增加 Copy 与 signal/wait 的最小队列依赖 | Draw/Dispatch 经同一提交与资源入口；消费者仅在生产者完成且数据可见后读取 |

本单元的目标是解释分层与职责。中断时序、硬件抢占、复杂复位和多 API 兼容都可以单独讲授，不加入最小共享合同。

### U7 图形与计算 UMD

**问题**：两个用户态入口如何使用一套底层设备而各自保留合适的对象模型？

| 任务 | 练习与改动 | 交付和通过条件 |
|---|---|---|
| U7.1 | 建立最小图形 UMD：资源/管线/绘制记录，委托给 HLI | 从图形入口运行 U1 或 U4 的一幅图，记录 UMD→HLI→KMD/FW→CP 的路径 |
| U7.2 | 建立最小计算 UMD：context/module/function、参数打包、launch、stream/event | 从计算入口运行 U5 的 vector_add/归约，参数、完成和错误可定位 |
| U7.3 | 用相同输入分别从直连 HLI 和对应 UMD 入口运行一个场景 | 选定结果和资源可见性符合相同参考；不要求内部命令编码或全部 trace 逐字节相同 |

图形实现思路可参考 Mesa；计算对象使用方式可参考公开 MUSA 资料。Vulkan/D3D12/OpenGL 适配器属于独立扩展，未实现时明确报告能力范围。

### U8 综合演示与教程

**问题**：两条路径能否围绕同一资源形成能看懂、能复现的完整故事？

| 任务 | 练习与改动 | 交付和通过条件 |
|---|---|---|
| U8.1 | 计算 UMD 把颜色或顶点写入共享 Buffer，signal 后图形 UMD 等待并读取 | 导出依赖计算结果的一帧；移除 wait 的教学实验要明确展示未保证的可见性而不作为正确结果 |
| U8.2 | 为一条数据记录应用参数、UMD/HLI、KMD/FW、CP、执行、内存和像素输出的关键事件 | 学习者可顺着一份短记录定位数据与完成点；关闭详细日志不改变结果 |
| U8.3 | 写可复现教程和边界说明，整理 C1–C6 检查点的输入/输出 | 干净检出后可运行核心场景；每个检查点有说明、参考和失败定位方式 |

综合演示只拼接经过选择的核心路径。选做的 Tess/GS、编译器、复杂缓存、外部 API 适配器不加入隐式前置条件。

## 4. 验收与修改原则

| 影响范围 | 处理方式 |
|---|---|
| 某个独立实验的参数或算法 | 更新该实验的输入、预期结果及说明，无需逐章同步 |
| 共用命令/资源/执行/同步含义 | 先改 [架构设计](architecture-design.md) 的边界，再更新受影响的接入练习 |
| 教学目标、单元依赖或最终检查点 | 更新 [README](README.md) 与本路线图 |
| 引入新的高级机制 | 在已有单元下增加独立实验；只有确实需要跨单元集成时才提升为共用接口 |

每项核心任务的硬条件是“选定场景正确、共享边界不矛盾、能解释结果”。局部 trace 格式、内部寄存器编号、缓存命中率和宿主执行耗时不是跨单元全局门禁。对内存可见性和队列依赖这种会改变最终结果的语义，综合路径需要统一约定。
