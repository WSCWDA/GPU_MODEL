# GPU_MODEL 架构设计：教学核心与可替换实验

> 本文配合 [项目主干](README.md) 和 [U0–U8 教学路线图](roadmap.md)，规定哪些模块必须共用、哪些实现可以独立。旧版以 42 章和精确 ABI 为中心的架构见 [重组前提交](https://github.com/WSCWDA/GPU_MODEL/commit/0b36b1d6dcdc25e1bcc958c5be642653943d0c7c)。旧版 design/stage 文档中的编号、容量和门禁是参考实例，不自动进入本版共享契约。

## 1. 两种运行方式

| 方式 | 目的 | 要求 |
|---|---|---|
| 局部教学实验 | 隔离一个概念，例如 wave 单步、TLB 查找或 Tess patch 暂存 | 可以使用自足的输入、替身对象和局部参考结果 |
| 综合路径 | 让真实的图形与计算示例经过相同底座并交换资源 | 共享命令、内存、执行入口和完成/可见性；能追踪跨层身份 |

U1 可由薄提交门面直接使用 hw_sim；U2/U3/U4/U5 的局部实验不必先构造完整驱动；U6 引入 HLI/KMD/FW；U7 将两种 UMD 接入；U8 使用综合路径。局部实验可以保留不同内部算法，综合路径需在共享边界统一语义。

## 2. 保留的驱动分层

| 层与目录 | 核心职责 | 教学阶段的最小实现 |
|---|---|---|
| common/ | 公共结果、资源标识、命令含义、执行入口和日志关联字段 | 只定义当前综合路径使用的类型 |
| hw_sim/core/ | 命令消费、CP、完成标识 | 简单 ring/队列和 clear/draw/dispatch/copy 分派 |
| hw_sim/memory/ | Buffer/View、地址访问、可见性 | flat 实现起步；映射/TLB/cache 可替换或独立实验 |
| hw_sim/shader/、hw_sim/isa/ | wave/lane 执行和 VS/CS 调用 | 内置 VS 逐步替换为小 ISA 解释器 |
| hw_sim/frontend/、raster/、om/、texture/、geometry/ | 图形专属的顶点、几何、像素和写回处理 | 最小三角形；纹理/深度/混合扩展；Tess/GS 可独立 |
| hw_sim/compute/、hw_sim/se/ | dispatch 到 workgroup/wave、逻辑调度 | 小网格与组内协作；CPU worker 承载并行 |
| firmware/ | 模拟取环与调度、完成通知 | 用明确事件推动 CP，不模拟真实固件时序 |
| kmd/ | 上下文、资源映射、提交与错误转发 | 一台逻辑设备和必要的上下文/队列 |
| hli/ | 上层共用的 Device/Resource/Command/Queue 入口 | 将图形与计算命令交给同一 KMD/FW 路径 |
| umd/graphics/、umd/compute/ | 各自的应用对象与命令生成 | 最小图形 draw 和计算 module/function/launch/stream/event |
| apps/、tools/、tests/ | 场景、导出、参考值、教学观测 | 每个单元一个可运行最小实例 |

目录是职责边界，不是开工时必须建满的空壳。初级路径中的薄门面是教学脚手架；进入 U6/U7 后，综合演示通过 HLI/驱动层提交。独立实验仍可使用脚手架。

调用与数据的主要方向是应用 → 对应 UMD → HLI → KMD → FW → hw_sim。底层不认识上层对象：hw_sim 不依赖 UMD/KMD，KMD 不执行 shader 指令，图形固定功能不承担计算驱动参数打包。各层可依赖 common 中的必要类型；工具优先消费稳定导出的数据。

## 3. 共享核心的最小语义

这里冻结的是**行为边界**，不是旧版某个数值化头文件。具体结构体和编码在实现这些边界时确定，并写入该实现的契约说明。

| 边界 | 综合路径必须一致 | 教学实验可自行决定 |
|---|---|---|
| 命令与提交 | 已接受的 Draw/Dispatch/Copy/Signal/Wait 按明确顺序消费；非法命令不会报告成功 | ring 大小、包号、MMIO 偏移、内部状态表示 |
| 资源与地址 | 资源标识有明确生命周期；读写经过同一内存入口；无效地址/权限可定位 | flat 或页表、TLB 形状、堆的数量、缓存替换策略 |
| 着色与执行 | VS/PS/CS 调用获得正确输入与 work-item 身份；越界或未激活 lane 不写出 | 指令位宽、寄存器分配、内部 wave 调度顺序 |
| 完成与可见性 | fence/event 宣告完成后，依赖该完成的消费者能看到规定的写入；等待关系可追踪 | 队列数量、事件实现、是否引入中断/模拟 tick |
| 错误与观测 | 失败标明所属场景/命令/资源或执行位置；结果可由独立参考检查 | 日志文件名、详细 trace 文本、统计项 |

出现跨实验冲突时先看它是否穿过此表的边界。未穿过边界的差异留在局部实验说明中；穿过边界的差异由接入方共同定义输入/输出样例，更新本表及受影响的单元练习。旧版 ADR、bit-budget 和固定 ABI 可以作为一种实现方案的材料，不再是所有教学实验的统一前置审批。

### 3.1 端到端数据路径

**图形**：顶点/状态 → 图形入口 → Draw → CP → IA/VS → 裁剪与图元装配 → 光栅 → OM → RT/导出。U1 使用内置 VS；U2 使用 wave/ISA；U4 可单独引入纹理、深度、混合或几何扩展。

**计算**：kernel/参数 → 计算入口 → Dispatch → CP → grid/workgroup/wave/lane → Buffer 写回。U5 先通过内部练习验证执行语义；U6/U7 才进入完整提交层。

**共享交换**：U8 使计算写入 Buffer，经 signal/wait 或 fence 建立可见性，再由图形读取。这里是两条路径必须使用同一资源和同步语义的最小证明。

### 3.2 GPU 模型与宿主 CPU

GPU 模型中的 wave、CU、缓存和内存层次是软件状态。宿主 CPU 的线程执行这些状态转移，宿主 L1/L2/L3 只影响程序的效率。允许用连续数组、线程局部缓冲和有界 WorkerPool 改进宿主局部性，但不得把宿主缓存的计数冒充 GPU L1/L2 事件。

同一 workgroup 内的 LDS、barrier 和 wave 状态由逻辑调度器管理；并行 WorkerPool 主要分配不同 workgroup 或 tile。无竞争结果应与单线程参考一致；原子/同步负载按明确的语义验证，未定义竞争不要求固定结果。

图形的顶点流、patch/control-point 与 GS 输出属于可教学的阶段局部暂存；它们可以单独演示复用，不强制接入通用 L1/L2 模型。缓存实验以数据来源和可见性为主，命中率只作解释性观测。

## 4. 哪些细节可以保留不同版本

| 情况 | 做法 |
|---|---|
| U2 小 ISA 与旧编译器文档编码不同 | 保持 U2 自己的 decode/执行测试；只在集成时提供符合当前 Shader 调用入口的产物 |
| U3 的页表布局与旧内存文档不同 | 保持 Buffer 访问和错误结果的共用含义；地址翻译布局由实验说明 |
| U4 的 Tess/GS 使用独立 patch 缓冲 | 作为几何实验；不把它误写为通用缓存或 U8 前置条件 |
| 图形与计算 UMD 的 API 形状不同 | 各自管理上层对象；统一落到 HLI 的资源、命令和完成语义 |
| 输出存在误差或非确定顺序 | 每个场景声明数据类型、参考值、容差及是否允许重排；不要用全局“逐字节一致”覆盖所有实验 |

全局固定数值只在它是选定综合路径的实际兼容条件时登记，例如一份具体实现的包布局或资源句柄表示。变更时只检查使用该条件的接入者；局部实验的替身与旧验收记录不会自动阻断。

## 5. 交付架构与拓展阅读

当前必须连通的一条链是：U1 图形基础路径 + U2 着色替换 + U3 资源访问 + U5 计算 + U6 共用提交 + U7 双 UMD + U8 数据交换。U4 的基本纹理或深度实验为最终画面提供可见变化；高级几何、编译器、更多固定功能、复杂故障处理和 API 适配器分别作为扩展。

旧 [设计模块](design/) 与 [stage1](stage1/)、[stage2](stage2/)、[stage3](stage3/) 中的具体包格式、stateId、场景编号、A 门禁和章节依赖体现原 42 章实现方案。选用其中的算法、图示或测试向量时，写清它在新实验中的输入、输出和与共享边界的关系。新的 U 单元任务以 [roadmap.md](roadmap.md) 为准。
