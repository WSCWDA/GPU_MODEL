# CPU 模拟 GPU 教学项目：文档导航与整体概览

> 本文件是项目导读与文档索引。项目目标、范围、正式阶段、工作包、展示里程碑及交付定义以[任务规划与实施规格](CPU模拟GPU教学项目_任务规划与实施规格.md)为主干；本文件不另设一套产品范围或任务编号。

## 项目要解决的问题

本项目用 CPU 实现一个可逐步观察、可重复验证的 GPU 功能模型。学习者可以从应用提交 draw/dispatch 开始，沿 UMD/HLI、KMD、固件、命令处理器和硬件单元追踪命令，观察图形结果写入 render target，或计算结果写回内存。

项目按图形优先的教学路径推进：先形成最小图形端到端闭环，再扩展 GPU 内存、缓存与写缓冲、执行并行、队列和驱动分层；计算管线在第 37 章收口，MUSA 风格计算驱动在 stage3 第 38–42 章完成。项目模拟功能行为，不模拟时钟周期、流水线时序、功耗或真实 GPU 性能。

## 正式阶段与主要成果

| 阶段 | 范围 | 学习与交付重点 |
|---|---|---|
| 初级图形闭环 | 第 1–9 章 | 命令和设备最小模型，VS 与固定功能图形阶段，完成首帧并导出图像 |
| 高级图形与共用底座 | 第 10–36 章 | KMD/FW/CP、地址翻译、内存与缓存、执行并行、图形 UMD、多队列与跨层协作 |
| 计算管线 | 第 37 章 | HLI 计算入口、DISPATCH、参数包、workgroup 调度与共用执行路径 |
| 计算驱动扩展 | stage3 第 38–42 章 | context/module/function、LaunchKernel、参数打包、stream/event、协作与双入口对照 |

第一帧图形需要 IA、VS、裁剪与图元装配、光栅化、深度/模板/混合与 OM 等阶段。VS 是可编程阶段；IA、裁剪/图元装配、光栅、OM 在本模型中作为固定功能单元。GS 和 Tessellation 属于高级几何扩展，不是第一帧前置要求；CS 属于计算路径，不混入图形第一帧。

## 关键设计边界

- 图形 draw 与计算 dispatch 共用命令、内存、队列、同步和执行模型；两条路径在入口与工作负载上分开。
- 主机 CPU 自身的 L1/L2/L3 仅影响模拟器运行速度。GPU 缓存作为软件模型显式实现，教学重点是缓存/写缓冲在数据通路中的位置、数据生产消费、复用、flush/invalidate 和可见性；hit/miss 计数仅作可选诊断。
- Tessellation 的 patch/control-point 数据、GS 输出等属于阶段局部暂存或输出缓冲，能展示跨阶段数据传递与复用，但不等同于通用 L1/L2 cache。
- CPU 多线程用于模拟多个 CU、wave 或独立引擎的并行执行；屏障、原子、队列依赖和最终输出仍须保持确定性。
- 第 36 章包含必要的错误路径和引擎复位实现，但核心展示聚焦图形 UMD、计算驱动、共用 HLI/KMD/FW 提交链和内存管理协作。

## 展示主线

任务规划中的 D1–D7 演示单元面向可观察结果：从 command packet/ring/CP/fence，到第一帧、内存与数据暂存、SIMT 协作，再到图形与计算入口经共用驱动栈下发，最后展示 LaunchKernel、stream/event 及双入口等价。每个演示单元对应的输入、探针和验收仍由 scene-specs 与 roadmap 细化。

## 开发参考

图形驱动与图形硬件分层可参考 Mesa 的公开实现；计算驱动对象与运行时流程可参考 MUSA 相关公开实现。GPU 架构思想可从 AMD、NVIDIA 及其他公开设计中借鉴。所有参考均用于提炼教学模型，不追求源码级移植或厂商兼容。
